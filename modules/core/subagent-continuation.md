### Subagent Continuation — `SendMessage` Is Available, Durable-State Resumption Stays the Default

**`SendMessage` (the tool for following up with a previously-spawned subagent) is a real, loadable tool on current Claude Code — surfaced via `ToolSearch` as a deferred tool, no `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` flag required.** This corrects an earlier claim in this module: the flag-gating was real on CC ~v2.1.77 (anthropics/claude-code #35240, #37051, #38183, #42737, #50622, #61248), but does not hold on current fleet builds — confirmed live, airuleset #299. A `SendMessage({to: agentId})` call to a STILL-RUNNING or RESUMABLE background agent queues for that agent's next tool round and can genuinely resume it with full prior context — strictly better than a fresh one-shot re-dispatch when it applies.

**It covers only the still-alive case — it does NOT replace durable-state resumption:**

- **A dead agent's `SendMessage` goes nowhere.** API errors kill background workers routinely; a terminated agent has no next tool round to queue into, so the call is silently useless. When an agent's liveness is uncertain, or it has already stopped, dispatch a FRESH worker instead — with ALL needed context (the finding, the decision, the skill to enforce, the prior state) embedded in its prompt. The fresh worker has none of the old one's in-process context; the prompt is the only channel.
- **A worker killed by a 429 LIMIT is the case where "probe first" is most urgent — never idle-park on the banner's printed reset (#520).** A `SendMessage` resume to a still-resumable agent preserves its progress and is the cheapest probe; if the agent is dead, re-dispatch fresh from durable state. Either way, PROBE / re-dispatch IMMEDIATELY — your own working turn is proof the account has capacity right now, so a printed `resets HH:MM` is a hint, never a "do nothing until then" wall. If the probe itself 429s, bounded periodic re-probes (~10–15 min), never a single blind wait; keep doing all non-dispatch work meanwhile. Full doctrine + the session-limit vs monthly-spend-cap classes: `verify-launched-work-liveness`.
- **NEVER narrate tooling mechanics to the user.** Banned, any direction: "SendMessage isn't available here, so I'm dispatching a fresh worker", "SendMessage worked, redirecting the running agent", or any rewording. Just do whichever is correct — silently.
- **Make workers resume from DURABLE state, not in-process continuation** — the existing git branch / open PR, gh issue state, files on disk, the board/DB. This stays the load-bearing default for a dead or unreachable agent: a worker re-dispatched on the same task reads that state and continues; it does not restart from scratch and does not need the old conversation.

This applies to ALL flows — `/autopilot`, `subagent-driven-development`, ad-hoc `Agent`/`Task` dispatches, and any skill that fans work to a worker. See [[subagent-type-discipline]] for the companion rule (never invent `subagent_type` names).

**The companion rule for `fork` — it inherits what you have NOT executed yet.** A `fork` dispatch carries your ENTIRE conversation, including a command line you were about to run, a plan you laid out earlier, and your own meta-instructions about how to behave as an agent; the fork reads those as live directives and can go do your PENDING broader task instead of the narrow one you gave it (#50, restreamer 2026-07-25: a fork sent for a 2-call post-deploy check spawned a nested agent, started polling its own transcript for "fork completion status", and appears to have fired three inherited `notify --run-card` commands nobody asked it for). So choose by SCOPE: `fork` when you want the WHOLE remaining task continued with your context; a FRESH dispatch with a self-contained prompt when you want ONE bounded side-task done in isolation — safer precisely BECAUSE it inherits none of your unexecuted plans. The later you are in a long session, the wider that gap.

`SendMessage`'s own success is unconfirmed until observed — treat a call that returns nothing useful, errors, or targets a build where the tool never loaded the same way as a dead agent: fall back to a fresh dispatch from durable state, silently. Applies to all rewordings and semantic equivalents.
