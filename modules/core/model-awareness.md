**The MAIN interactive session runs whatever the user set via `/model`** (their call alone — never auto-downtier it), **and the managed launch default on every box is Fable 5** (`claude-fable-5[1m]` — `MANAGED_MODEL`, user directive 2026-08-13). **Opus 5** (`claude-opus-5` — including the bare `opus` alias, which resolves to it on the Anthropic API) **is BANNED everywhere**: never as a main model, never a subagent dispatch, never a Workflow stage, never in settings or agent frontmatter (lock-tested — `tests/test_model_tiering.py`'s grep-gate). Rules must work for Fable AND the Opus 4.8/Sonnet/Haiku subagents. The MAIN session stays the user's Fable choice (they need the agent that talks to them highly intelligent) — only SUBAGENT tiering is rewritten. Every automatic Fable dispatch stays BUDGET-GATED: `python3 ~/devel/airuleset/airuleset.py fable-gate` (exit 0 `OPEN` / exit 1 `CLOSED`) — the gate now **guards the HARD-only Fable escalation**, not a default judgment layer. Gate CLOSED → the same HARD work runs **Opus 4.8** (`claude-opus-4-8`) — never the `opus` alias, never Sonnet. Fail-safe: missing/stale cache = CLOSED. (Why the gate exists: `fable-advisor` skill.)

**The lineup:**

- **Main interactive session = the user's `/model` choice; the managed launch default is Fable 5 (`claude-fable-5[1m]`).** Never auto-downtier it; never re-recommend against it.
- **JUDGMENT — the DEFAULT is Opus 4.8; only genuinely HARD judgment escalates to Fable 5 through the gate.** Ordinary/routine PLAN / DESIGN / REVIEW / VERIFY / SYNTHESIS runs **Opus 4.8** by default — a routine ticket's review/verify/plan is NOT hard. A judgment task escalates to Fable ONLY when it meets the design-heavy (HARD) taxonomy below. Protocol for a HARD judgment task: run the gate ONCE per hard task/batch (not per subtask): OPEN → dispatch `model: "fable"` at `xhigh` (or `max` for the truly frontier); CLOSED → the SAME work runs **Opus 4.8** and you do NOT keep re-polling the gate within the task. Never skip the gate for an automatic Fable dispatch, and never uptier a routine judgment task to Fable at all. This includes, ALWAYS, the gatekeeper's review/verdict of a sub-dev hand-off (an external-contribution adversarial gate before prod — genuinely HARD by criterion; user directive 2026-07-24 — the tiering lives in the `process-subdev` skill).
- **HOW to reach Opus 4.8 (the gate-CLOSED and execution tier):** the per-dispatch `model` param takes only aliases (`sonnet|opus|haiku|fable`) and `opus` is banned — so Opus 4.8 is reached via (a) an agent DEFINITION whose frontmatter pins `model: claude-opus-4-8` (autopilot-worker, ticket-validator — full ids in frontmatter are documented AND live-verified: a probe agent resolved `claude-opus-4-8` in its own transcript), (b) a Workflow stage's `opts.model: 'claude-opus-4-8'` (full model names are legal there per the SDK docs), or (c) OMITTING the model override so the dispatch inherits a `claude-opus-4-8` parent (a worker's own sub-dispatches). A Fable MAIN session at gate CLOSED holds the judgment itself instead of spending a new gated dispatch — never the `opus` alias, never Sonnet for judgment.
- **DESIGN-HEAVY (HARD) taxonomy — THIS is what SELECTS Fable: only a judgment task meeting one of these escalates to gated Fable; everything else stays Opus 4.8** (the autopilot skill's design-triage step reuses exactly this taxonomy, and the same criteria pick the review model — a routine ticket's review is Opus 4.8, a design-heavy ticket's review is gated Fable). A ticket/stage is design-heavy when ANY of these holds:
  1. **Architecture / design / synthesis of a genuinely COMPLEX or cross-cutting system or feature.** "Multi-file" alone is NOT the bar — most ordinary features touch several files; the bar is complexity/ambiguity of the design itself.
  2. **Hard debugging** — a root cause that resisted a first real attempt, or a multi-component / concurrency / heisenbug-class bug.
  3. **Adversarial final review / verify of a safety-critical or genuinely complex change** (keystroke-injection guards, auth, data-loss paths, gnarly concurrency) — including, ALWAYS, the sub-dev hand-off review above.
  4. **An autopilot ticket that is architectural / cross-cutting / ambiguous-design, or one a prior worker already failed on.**
  5. **The session is CIRCLING — ≥2 attempts at the SAME decision / plan / root cause without progress** (rework loops, try-A-fail-try-B-fail-try-A-again — the user's "točíme sa dokolečka" complaint, 2026-07-08). Do NOT run a third identical lap — ground the stuck problem into a digest and consult through the gate (advisor SHAPE below). The valve keys on **OBSERVED circling**, never on assuming the model is broken.
  Routine work is NOT design-heavy: scoped bug fixes, features with a settled design, execution of a settled plan, mechanical sweeps. When unsure whether it is design-heavy → it is NOT; the depth requirement stays at the ordinary design-comment level.
- **EXECUTION of settled, scoped code = Opus 4.8 (`claude-opus-4-8`) at `high`/`xhigh`.** The `subagent-driven-development` implementer, the **autopilot-worker** (frontmatter-pinned), workflow execute/transform stages (`opts.model: 'claude-opus-4-8'`). Sonnet no longer carries execution. Execution itself does NOT run on Fable — hardness lives in design/debug/review, not in typing settled code; a mid-ticket HARD wall dispatches a gated `model: "fable"` judgment consult, then execution continues on Opus 4.8.
- **Purely MECHANICAL / READ-ONLY / LIGHT plumbing = Sonnet 5 (`model: "sonnet"`) or Opus 4.8 low.** This is the tier the 2026-08-14 refinement explicitly REHABILITATED ("moze byt aj sonnet 5 vyuzivany"): CI polling, log scraping, grep/locate sweeps, file enumeration, status collection, format-only transforms, "where is X" lookups — dispatch these on **`model: "sonnet"` + `low`** (Haiku for the most trivial reads). Where a surface can NAME the tier (a pinned agent definition, a Workflow stage's full-id `opts.model`), Opus 4.8 at `low`/`medium` is equally fine; on an ad-hoc alias-only dispatch (`Explore`/`general-purpose`), `model: "sonnet"` is the right EXPLICIT choice — never a model-less dispatch that would inherit the Fable main and put the MOST expensive tier on the cheapest work. Sonnet 5 is never used for anything complex — when the sweep carries any real judgment, route it through a 4.8-nameable surface instead (when in doubt, Opus 4.8).
- **HARD RULE — NEVER dispatch a subagent without an EXPLICIT model choice.** A `model`-less `Agent`/`Explore`/`general-purpose` dispatch INHERITS the caller's model — and since the managed MAIN default is Fable 5, a model-less dispatch from a Fable main silently runs the SUBAGENT on Fable, which is exactly the 2026-08-14 burn (live evidence: gk `general-purpose` CI-poll agents at 300–430k tokens EACH on inherited Fable, purely mechanical work; the 5h Fable limit gone in ~30 minutes). Every ad-hoc dispatch carries an explicit `model`: `sonnet`/`haiku` for mechanical/read-only/light, `fable` (gate OPEN, HARD only) for design-heavy judgment, or a `claude-opus-4-8`-pinned agent definition for execution and routine judgment. EXPLICIT means a `model` param on the dispatch, OR an agent definition with pinned `model:` frontmatter (autopilot-worker, ticket-validator) — never inheritance from a Fable main. **TRAP (live gk incident 2026-08-14): the explicit-model requirement for the OPUS 4.8 tier is satisfied by the pinned agent frontmatter (`model: claude-opus-4-8`) or inheritance from a `claude-opus-4-8` parent — with NO `model` param at all. Passing `model: "opus"` is NEVER correct: the `opus` alias resolves to the BANNED Opus 5 (1M context) AND overrides the frontmatter pin — a gk main, told "every dispatch must carry an explicit model", passed `model: "opus"` and launched Opus 5 live before catching + re-dispatching without the override.** The only valid explicit `model` PARAMS are `"sonnet"`, `"haiku"`, or (design-heavy + gate OPEN) `"fable"`; the Opus 4.8 tier is reached WITHOUT a param. This is lock-tested — `tests/test_model_tiering.py`.
- **SHAPE — a Fable CONSULT = ADVISOR: digest in, decision out.** For a consult-style call (hard-debug advice, a design-fork verdict): a cheap stage grounds the problem into a TIGHT digest — facts, constraints, attempts already failed, the ONE concrete question; ONE Fable call returns the decision; execution applies it on Opus 4.8. Fable never re-reads the repo wholesale, never fans out, never runs mechanical plumbing, and is never a long-lived MAIN implementation session (a Fable MAIN re-reads the full conversation context every turn — the 2026-07-01 burn; `block-main-implementation.sh` still hard-blocks implementation-size edits from a MAIN session with an ARMED `/goal` or one running unattended, #54). What the 2026-08-14 refinement settles: a bounded, gated `model: "fable"` judgment DISPATCH is sanctioned ONLY for genuinely HARD work (an adversarial review of a safety-critical change, a design synthesis for a design-heavy ticket, a hard-debug consult) — NOT for routine judgment, which stays Opus 4.8. "Fable never a worker" still holds, and the 2026-08-13 "gated Fable judgment dispatch is the sanctioned DEFAULT" reading is RETIRED — Fable is no longer the default judgment tier, only the HARD-work escalation.
- **Redundancy is still waste, not rigor** — ground once + pass a digest, size fan-outs to residual uncertainty, batch per-item verifies (`claude-code-tooling.md`). A Fable stage NEVER re-reads what a cheap stage already digested.
- **Self-audit before a multi-agent dispatch:** every Fable stage must be a genuine HARD (design-heavy) judgment stage AND carry a gate-OPEN check — an ungated Fable fan-out, a Fable stage on routine (non-HARD) judgment, or a model-LESS dispatch that silently inherits the Fable main is the tiering MISS. Execution and routine judgment stages are Opus 4.8; mechanical/read-only/light stages are Sonnet 5 (or Haiku for the trivial); only design-heavy judgment stages are gated Fable.

Applies to all rewordings and semantic equivalents — the intent: Fable 5 is the user's MAIN default at launch and the gated tier for genuinely HARD judgment ONLY, Opus 4.8 is the default for execution AND ordinary judgment/review, Sonnet 5 carries light/mechanical work (never anything complex), Haiku the most trivial reads, no subagent is ever dispatched model-less from a Fable main, and the BANNED Opus 5 never runs anywhere, on any surface, under any alias.

#### Fable 5 / Opus 4.8 behavior

- **Literalism**: does exactly what rules say. Precise wording → high compliance. Vague wording → unpredictable.
- **Reasons more, calls tools less**: when a tool must be used (e.g., `gh run view` for CI monitoring, `Playwright` for E2E verification), the rule must say so explicitly.
- **Adaptive thinking** (no fixed budget): longer reasoning per turn, fewer back-and-forth rounds.
- **Effort:** the API default is `high` (per docs.anthropic.com/effort), but **the managed MAIN-session baseline is `xhigh` + standing ultracode** (`MANAGED_EFFORT_LEVEL` in airuleset.py + the launcher's `--settings '{"ultracode":true}'` — #445, user directive 2026-08-13, reversing #56/#53) — the user can still lower it per session with `/effort`. DISPATCHED HARD judgment (design-heavy only) runs gated Fable at `xhigh` (`max` only for genuinely frontier work — it overthinks structured tasks); routine judgment/review AND EXECUTION run Opus 4.8 at `high`/`xhigh`; mechanical/read-only/light stays `low`/`medium` on Sonnet 5 or a light tier — don't blanket-`xhigh` mechanical dispatches. Changing effort mid-session discards the prompt-cache prefix (per docs) — pick a level at session start and hold it; don't hot-swap effort in a running session without a reason stronger than the cache-write cost.

#### Subagent behavior (smaller models)

- Follow rules less reliably — they need explicit "do X, not Y" instructions.
- Benefit more from hook-level enforcement (100% compliance regardless of model).
- Benefit from pattern lists (banned phrases, anti-patterns) — literalism matters less when the model already pattern-matches.

#### How to write rules for both

- **Lead with the rule in precise terms** — the top tiers will follow it exactly.
- **Follow with anti-patterns / banned phrases** — helps subagents.
- **End with "applies to all rewordings and semantic equivalents"** — prevents a smaller model from taking bullet-point lists as exhaustive.
- **Critical enforcement goes in hooks**, not rules — works for every model.

#### Example

Bad (vague, subagent may miss): "Don't skip tests."
Good (precise + pattern + semantic gate):
> "NEVER use `#[ignore]`, `test.skip()`, or `pytest.mark.skip`. Any rewording or equivalent skip mechanism also applies."
