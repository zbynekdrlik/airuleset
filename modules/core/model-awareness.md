#### Model tiering — Fable 5 judgment + Opus 4.8 execution; Opus 5 BANNED (ACTIVE policy, 2026-08-13 — replaces 2026-07-03)

*(This section is the GENERAL tiering policy. `claude-code-tooling.md` → "Tier the model PER STAGE" restates the same tiers as their Workflow-specific application (`opts.model`/`opts.effort` per `agent()` stage) — that overlap is INTENTIONAL, not a dedup target: general policy here, its Workflow application there.)*

**The standing directive (2026-08-13, verbatim):** *"intenet je plny obrovskej nespokojnosti s opus 5, chcem prerobit pravidla opus 5 sa nesmie pouzivat chcem aby sa pozival by default pri spusteni claude fable a ked sa vytvara subagent tak aby to bol bud fable alebo opus 4.8 nikdy opus 5!"* — refined the same day: *"hlavne nie ze pouzijes sonnet na zlozite veci, radsej by som mal ze kde bol opus 5 bude fable a kde bol sonnet bude opus 4.8"*. Where Opus 5 sat, **Fable 5** goes; where Sonnet 5 sat, **Opus 4.8** goes. Every automatic Fable judgment dispatch stays BUDGET-GATED: `python3 ~/devel/airuleset/airuleset.py fable-gate` (exit 0 `OPEN` / exit 1 `CLOSED`) — the gate now **guards the DEFAULT judgment layer**, not an exceptional escalation. Gate CLOSED → the same work runs **Opus 4.8** (`claude-opus-4-8`) — never the `opus` alias, never Sonnet. Fail-safe: missing/stale cache = CLOSED. (Why the gate exists: `fable-advisor` skill.)

**The lineup:**

- **Main interactive session = the user's `/model` choice; the managed launch default is Fable 5 (`claude-fable-5[1m]`).** Never auto-downtier it; never re-recommend against it.
- **JUDGMENT — PLAN / DESIGN / ARCHITECTURE / SYNTHESIS / hard-debug / adversarial REVIEW + VERIFY = Fable 5 through the gate.** Protocol: run the gate ONCE per judgment task/batch (not per subtask): OPEN → dispatch `model: "fable"` at `xhigh` (or `max` for the truly frontier); CLOSED → the SAME work runs **Opus 4.8** and you do NOT keep re-polling the gate within the task. Never skip the gate for an automatic Fable dispatch. This includes, ALWAYS, the gatekeeper's review/verdict of a sub-dev hand-off (external-contribution gate before prod; user directive 2026-07-24 — the tiering lives in the `process-subdev` skill).
- **HOW to reach Opus 4.8 (the gate-CLOSED and execution tier):** the per-dispatch `model` param takes only aliases (`sonnet|opus|haiku|fable`) and `opus` is banned — so Opus 4.8 is reached via (a) an agent DEFINITION whose frontmatter pins `model: claude-opus-4-8` (autopilot-worker, ticket-validator — full ids in frontmatter are documented AND live-verified: a probe agent resolved `claude-opus-4-8` in its own transcript), (b) a Workflow stage's `opts.model: 'claude-opus-4-8'` (full model names are legal there per the SDK docs), or (c) OMITTING the model override so the dispatch inherits a `claude-opus-4-8` parent (a worker's own sub-dispatches). A Fable MAIN session at gate CLOSED holds the judgment itself instead of spending a new gated dispatch — never the `opus` alias, never Sonnet for judgment.
- **DESIGN-HEAVY (HARD) taxonomy — kept as the design-DEPTH classifier, no longer a model picker** (all judgment is gated Fable either way; the autopilot skill's design-triage step reuses exactly this taxonomy). A ticket/stage is design-heavy when ANY of these holds:
  1. **Architecture / design / synthesis of a genuinely COMPLEX or cross-cutting system or feature.** "Multi-file" alone is NOT the bar — most ordinary features touch several files; the bar is complexity/ambiguity of the design itself.
  2. **Hard debugging** — a root cause that resisted a first real attempt, or a multi-component / concurrency / heisenbug-class bug.
  3. **Adversarial final review / verify of a safety-critical or genuinely complex change** (keystroke-injection guards, auth, data-loss paths, gnarly concurrency) — including, ALWAYS, the sub-dev hand-off review above.
  4. **An autopilot ticket that is architectural / cross-cutting / ambiguous-design, or one a prior worker already failed on.**
  5. **The session is CIRCLING — ≥2 attempts at the SAME decision / plan / root cause without progress** (rework loops, try-A-fail-try-B-fail-try-A-again — the user's "točíme sa dokolečka" complaint, 2026-07-08). Do NOT run a third identical lap — ground the stuck problem into a digest and consult through the gate (advisor SHAPE below). The valve keys on **OBSERVED circling**, never on assuming the model is broken.
  Routine work is NOT design-heavy: scoped bug fixes, features with a settled design, execution of a settled plan, mechanical sweeps. When unsure whether it is design-heavy → it is NOT; the depth requirement stays at the ordinary design-comment level.
- **EXECUTION of settled, scoped code = Opus 4.8 (`claude-opus-4-8`) at `high`/`xhigh`.** The `subagent-driven-development` implementer, the **autopilot-worker** (frontmatter-pinned), workflow execute/transform stages (`opts.model: 'claude-opus-4-8'`). Sonnet no longer carries execution. Execution itself does NOT run on Fable — hardness lives in design/debug/review, not in typing settled code; a mid-ticket HARD wall dispatches a gated `model: "fable"` judgment consult, then execution continues on Opus 4.8.
- **Purely MECHANICAL / READ-ONLY plumbing = Opus 4.8 at `low`/`medium` where the surface can name it (a pinned agent definition, a Workflow stage's full-id `opts.model`); on an ad-hoc alias-only dispatch (`Explore`/`general-purpose` delegated reads, where 4.8 is structurally unreachable and inheriting the Fable main would put the MOST expensive tier on the cheapest work) → `model: "sonnet"` + `low` — for READ-ONLY collection only, never judgment; Haiku for the most trivial reads.** File enumeration, log scraping, grep/locate sweeps, "where is X" lookups. Sonnet 5 is never used for anything complex — when the sweep carries any real judgment, route it through a 4.8-nameable surface instead (when in doubt, Opus 4.8).
- **SHAPE — a Fable CONSULT = ADVISOR: digest in, decision out.** For a consult-style call (hard-debug advice, a design-fork verdict): a cheap stage grounds the problem into a TIGHT digest — facts, constraints, attempts already failed, the ONE concrete question; ONE Fable call returns the decision; execution applies it on Opus 4.8. Fable never re-reads the repo wholesale, never fans out, never runs mechanical plumbing, and is never a long-lived MAIN implementation session (a Fable MAIN re-reads the full conversation context every turn — the 2026-07-01 burn; `block-main-implementation.sh` still hard-blocks implementation-size edits from a MAIN session with an ARMED `/goal` or one running unattended, #54). What changed 2026-08-13: a bounded, gated `model: "fable"` judgment DISPATCH (an adversarial review pass, a design synthesis, a plan) is the sanctioned DEFAULT now, not an exception — "Fable never a worker" survives only as "Fable never types settled code and never grounds itself wholesale".
- **Redundancy is still waste, not rigor** — ground once + pass a digest, size fan-outs to residual uncertainty, batch per-item verifies (`claude-code-tooling.md`). A Fable stage NEVER re-reads what a cheap stage already digested.
- **Self-audit before a multi-agent dispatch:** every Fable stage must be a genuine JUDGMENT stage AND carry a gate-OPEN check — an ungated or mechanical-work Fable fan-out is still the tiering MISS. Execution/mechanical stages are Opus 4.8 (or sonnet/haiku for the trivial); judgment stages are gated Fable.

Applies to all rewordings and semantic equivalents — the intent: Fable 5 is the default at launch and the (budget-gated) judgment tier, Opus 4.8 executes and is the gate-CLOSED fallback, Sonnet never touches anything complex, and the BANNED Opus 5 never runs anywhere, on any surface, under any alias.

#### Fable 5 / Opus 4.8 behavior

- **Literalism**: does exactly what rules say. Precise wording → high compliance. Vague wording → unpredictable.
- **Reasons more, calls tools less**: when a tool must be used (e.g., `gh run view` for CI monitoring, `Playwright` for E2E verification), the rule must say so explicitly.
- **Adaptive thinking** (no fixed budget): longer reasoning per turn, fewer back-and-forth rounds.
- **Effort:** the API default is `high` (per docs.anthropic.com/effort), but **the managed MAIN-session baseline is `xhigh` + standing ultracode** (`MANAGED_EFFORT_LEVEL` in airuleset.py + the launcher's `--settings '{"ultracode":true}'` — #445, user directive 2026-08-13, reversing #56/#53) — the user can still lower it per session with `/effort`. DISPATCHED judgment work runs gated Fable at `xhigh` (`max` only for genuinely frontier work — it overthinks structured tasks); EXECUTION runs Opus 4.8 at `high`/`xhigh`; mechanical/read-only stays `low`/`medium` on a light tier — don't blanket-`xhigh` mechanical dispatches. Changing effort mid-session discards the prompt-cache prefix (per docs) — pick a level at session start and hold it; don't hot-swap effort in a running session without a reason stronger than the cache-write cost.

#### Subagent behavior (smaller models)

- Follow rules less reliably — they need explicit "do X, not Y" instructions.
- Benefit more from hook-level enforcement (100% compliance regardless of model).
- Benefit from pattern lists (banned phrases, anti-patterns) — literalism matters less when the model already pattern-matches.

#### How to write rules for both

- **Lead with the rule in precise terms** — the top tiers will follow it exactly.
- **Follow with anti-patterns / banned phrases** — helps subagents.
- **End with "applies to all rewordings and semantic equivalents"** — prevents a smaller model from taking bullet-point lists as exhaustive.
- **Critical enforcement goes in hooks**, not rules — works for every model.

#### Example

Bad (vague, subagent may miss): "Don't skip tests."
Good (precise + pattern + semantic gate):
> "NEVER use `#[ignore]`, `test.skip()`, or `pytest.mark.skip`. Any rewording or equivalent skip mechanism also applies."
