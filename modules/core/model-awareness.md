### Model Awareness (2026)

**The MAIN interactive session runs whatever the user set via `/model`** (their call alone — never auto-downtier it). **Opus 5** (`opus`, `claude-opus-5`) is now the default main + judgment tier: measured within 0.5% of Fable 5 on CursorBench 3.2 at HALF the price (https://www.anthropic.com/news/claude-opus-5), and Opus 5 ships thinking ON by default (a change from 4.8, where it was opt-in) — Fable 5 cannot disable thinking at all, so its output tokens are structurally higher than Opus's for the same task. **Honest history (2026-07-25 rewrite):** earlier in 2026 the user ran Fable 5 as MAIN by hand — a deliberate WORKAROUND, not a taste preference: Opus 4.8 was regressing (the CIRCLING valve below exists because of it) and Sonnet 5 could not reliably carry the coordinator role, so Fable was the only model that held up as main. Opus 5 retires that workaround: the regression + the Sonnet coordinator gap that made Fable-as-main necessary are both gone, so the recommended default flips back to Opus 5. This is NOT a ban on Fable as main — the user's `/model` choice stays theirs alone, gated on nothing — but recommend Opus 5 and say so plainly ONCE per session when the main session is still running Fable, so the user knows the workaround it once needed no longer applies (never nag every turn). Dispatched EXECUTION defaults to **Sonnet 5** (`sonnet`, `claude-sonnet-5`, full effort range `low`–`max`; trails Opus on agentic-coding benchmarks but at a fraction of the cost). Above Opus (barely, per CursorBench) sits **Fable 5** (`claude-fable-5`, the `fable` alias — Anthropic's Mythos-class tier, the most intelligent generally-available Claude, Claude 5 family; a first-class subagent `model` value): genuinely HARD tasks escalate to it AUTOMATICALLY through the **budget gate** (`airuleset.py fable-gate`) — it burns tokens fast, so it is never a blanket default and every automatic use is gated on weekly-limit headroom. Haiku 4.5 (`haiku`) for the most trivial reads. Pricing per Mtok in/out (official pricing page, 2026-07-25): Fable 5 $10/$50 · Opus 5 $5/$25 (cache read $0.50, cache write $6.25 5-min / $10 1-hour) · Sonnet 5 $2/$10 · Haiku 4.5 $1/$5; ALL current models ship the 1M context window at standard pricing. Rules must work for Opus AND the Sonnet/Haiku subagents. #### Model tiering — Opus 5 + Sonnet 5 default; Fable 5 AUTO-escalates on genuinely HARD tasks, budget-gated (ACTIVE policy, 2026-07-03)

*(This section is the GENERAL tiering policy. `claude-code-tooling.md` → "Tier the model PER STAGE" restates the same tiers as their Workflow-specific application (`opts.model`/`opts.effort` per `agent()` stage) — that overlap is INTENTIONAL, not a dedup target: general policy here, its Workflow application there.)*

**History that shapes this policy:** the 2026-07-01 Fable-everywhere mode burned tokens brutally and kept tripping the usage limits mid-work — the user reverted it 2026-07-02 (reverted the 2026-07-01 policy). New standing directive (2026-07-03): the user does NOT want all work to be only Opus + Sonnet — **genuinely HARD tasks escalate to Fable 5 AUTOMATICALLY** (in autopilot, brainstorming/design, workflows, hard debugging), WITHOUT asking. What makes this safe where Fable-everywhere was not: (1) only the HARD subset escalates (routine work stays Opus/Sonnet), and (2) **every automatic escalation is BUDGET-GATED** — `python3 ~/devel/airuleset/airuleset.py fable-gate` (exit 0 `OPEN` / exit 1 `CLOSED`) checks the Fable weekly + shared weekly windows from the watchdog's usage cache and closes automatic Fable once headroom runs out (default gate 80%, env `AIRULESET_FABLE_GATE_PCT`), so the limit-trip-stops-work failure cannot repeat. Gate CLOSED → the same task runs Opus. Fail-safe: missing/stale cache = CLOSED. (The 5-hour session window intentionally does NOT gate — only the weekly windows do; don't 'fix' that.)

**The lineup:**

- **Main interactive session = the user's `/model` choice.** Never auto-downtier it; the user flips it (incl. to Fable) BY HAND when they want — Opus 5 is simply the now-recommended default (above), not an enforced floor.
- **PLAN / DESIGN / ARCHITECTURE / SYNTHESIS / hard-debug / adversarial REVIEW + VERIFY = Opus 5 by default.** The judgment bookends — deciding WHAT to build and whether it is correct — run Opus (dispatch `model: "opus"`, or inherit Opus)… unless the task is genuinely HARD (below), in which case it auto-escalates to Fable through the gate.
- **HARD-task AUTO-escalation = Fable 5 (`model: "fable"`), budget-gated.** A task is HARD when ANY of these holds:
  1. **Architecture / design / synthesis of a genuinely COMPLEX or cross-cutting system or feature** — the design synthesis of a substantial brainstorm, the plan for a cross-cutting change, a judge/synthesis stage of a Workflow on a hard problem. "Multi-file" alone is NOT the bar — most ordinary features touch several files; the bar is complexity/ambiguity of the design itself, and the design of a routine feature stays Opus.
  2. **Hard debugging** — the root cause resisted a first Opus-tier attempt, or the bug is multi-component / concurrency / heisenbug-class.
  3. **Adversarial final review / verify of a safety-critical or genuinely complex change** (keystroke-injection guards, auth, data-loss paths, gnarly concurrency) — **including, ALWAYS, the gatekeeper's review/verdict of a sub-dev hand-off** (external-contribution gate before prod; user directive 2026-07-24 — maximum scrutiny on sub-dev submitted PRs/tickets; the tiering lives in the `process-subdev` skill step 3.1b).
  4. **An autopilot ticket that is architectural / cross-cutting / ambiguous-design, or one a prior worker already failed on.**
  5. **Opus is CIRCLING — the session has looped ≥2 attempts at the SAME decision / plan / root cause without progress** (rework loops, try-A-fail-try-B-fail-try-A-again, repeatedly wrong calls on one fork — the user's "točíme sa dokolečka" complaint, 2026-07-08). The NEXT judgment step on that fork is HARD: do NOT run a third identical Opus lap — ground the stuck problem into a digest and consult Fable through the gate (advisor SHAPE below). This is the self-correcting valve for any Opus-quality wobble (July-2026 community reports of Opus 4.8 degradation: anthropics/claude-code#68780 open with no official response; Marginlab's independent statistical tracker attributed the pre-4.8 drop to a HARNESS issue and confirms no 4.8 model regression so far — so the valve keys on OBSERVED circling, never on assuming the model is broken).
  Routine work is NOT hard: scoped bug fixes, features with a settled design, execution of a settled plan, mechanical/read-only sweeps — those stay Sonnet/Opus per the rows here. When unsure whether a task is hard → it is NOT; use Opus.
  **Protocol:** run the gate ONCE per hard task/batch (not per subtask): `python3 ~/devel/airuleset/airuleset.py fable-gate` → `OPEN` → dispatch `model: "fable"` at `xhigh` (or `max` for the truly frontier); `CLOSED` → dispatch `model: "opus"` and do NOT keep re-polling the gate within the same task. Never skip the gate for an automatic escalation — an ungated automatic Fable dispatch is the exact failure the user reverted. (The user's own manual `/model` Fable is not gated — that's their call.)
  **SHAPE — Fable escalation = ADVISOR, never worker (the anti-burn form, 2026-07-08).** The 2026-07-01 burn came from Fable doing EVERYTHING — grounding, reading, executing — at Fable pricing (and Fable as the MAIN-session model re-reads the full conversation context every turn, which alone ate a Max plan in under an hour). An escalation therefore dispatches Fable as a one-shot ADVISOR: a cheap stage (Sonnet, or the session itself) grounds the problem into a TIGHT digest — facts, constraints, attempts already failed, the ONE concrete question; then ONE Fable call receives digest + question at `xhigh` and returns the decision / plan / verdict; Sonnet 5 (or Opus) executes it. Fable never re-reads the repo wholesale, never fans out, never types settled code, and is never dispatched as a long-lived worker session. Community-relayed, UNVERIFIED indicative numbers (July 2026, no primary source): advisor + Sonnet-5-executor ≈ 92% of Fable-solo quality at ~63% of the cost — and the budget gate still sits on top. This SHAPE applies to every automatic Fable dispatch, including Workflow `opts.model: 'fable'` stages. **Two teeth since 2026-07-24 (#32):** the `fable-advisor` skill is the one-command ADVISOR path (gate → digest → ONE fable call → Sonnet executes) for a master on a cheaper model, and `block-main-implementation.sh` (PreToolUse) HARD-blocks a Fable MAIN session from typing implementation-size edits (>~20 lines) — Fable main does decisions/oversight/surgical edits, workers type the code (the presenter incident: a Fable main implemented a whole issue itself despite this prose). **Generalized 2026-07-25 (#54):** the SAME hook (renamed from `block-fable-main-implementation.sh`) now ALSO blocks implementation-size edits from a MAIN session with an ARMED `/goal`, on ANY model — the autopilot contract is main = coordinator, dispatched worker = implementer, and that discipline doesn't stop applying just because the model isn't Fable. Live case: david@subdev's Opus main, with an armed `/goal`, did 354 direct Edits + 56 Writes alongside 229 Agent dispatches (context 0 → 271K in ~7 minutes) — the exact "main implements instead of dispatching" failure, on a non-Fable model. Goal-armed detection reads the session TRANSCRIPT for Claude Code's own `<local-command-stdout>Goal set:` / `Goal cleared:` marker (a hook has no reliable pane access) and is fully INDEPENDENT of the Fable-model detection above — it does not read or depend on `MODEL`, so it neither triggers nor is affected by #38's stale-model-after-`/model`-switch caveat. Why the MAIN-session default matters (2026-07-25): across the 6 managed boxes over 8 days, Fable running as MAIN (not advisor) accounted for 76% of a ~$13,600 token spend — this SHAPE constrains every AUTOMATIC escalation, but MAIN-session choice sat outside its scope until now; Opus 5 shipping (above) closes that gap by giving MAIN a tier that no longer needs the Fable-as-main workaround. **Generalized again 2026-07-26 (#66) to guard `Bash`:** measured that day (`loop_health.py`, gatekeeper session, one hour of an armed `/goal` loop): 1222 main-agent Bash calls vs only 97 subagent dispatches at a 212K-avg context — every one of those Bash calls re-sends the whole context, making raw main-agent Bash turn-count the dominant remaining cost lever now that context SIZE is handled (compaction, #65/#67/#69). The same hook now ALSO fires on `PreToolUse(Bash)` under the identical Fable-main/goal-armed gate, but classifies the COMMAND instead of sizing the payload: a conservative ALLOW-LIST (`gh pr/issue/run view|list|create|comment|edit|close`, `git status/rev-parse/fetch/log --oneline -N`, `python3 airuleset.py ...`, `tmux`, `systemctl --user`) always passes; a BLOCK-LIST of bulk read/search/build/test/log-scrape commands (`grep`/`rg`/`find`, `cat`/`head`/`tail`/`sed`/`awk`, `pytest`/`cargo test`/`npm test`/lint runs, `journalctl`/`docker logs`) is rejected ONLY under that gate; a command matching NEITHER list is ambiguous and stays ALLOWED — conservative by design, so a legitimate gh/git coordination call the loop depends on is never broken. **Corrected 2026-07-26 (#80) — the command's CLASS was the wrong variable.** Measured on gk the next day: `/tmp/airuleset-main-exec-block.log` did not exist at all and the ratio was UNCHANGED (main Bash 687 : Agent 22 = 31:1). Two causes, both now fixed: (a) the classifier FALSE-POSITIVED on `cat > body.md <<'EOF' … EOF` — the very recipe `gh-cli-recipes.md` mandates — so the main armed the bypass marker and the hook was dead for 17 hours (332 bypasses); the marker is now ONE-SHOT (honoring it consumes it, re-touching always works, so it can never again be a session-long off switch), heredoc bodies are stripped before classification, only a statement's FIRST pipe stage is classified (an `… | tail -2` reducer is not a bulk read), and a read is judged by the SIZE that comes back (`head -5`, `tail -3`, `sed -n '250,260p'`, `grep -c` pass; `cat file`, `grep -rn`, a wide slice do not). (b) The real lever is the COUNT of main-agent turns, not their class — every turn re-sends the whole 256-363K context, so a `gh issue view` costs what a `grep` costs. The hook therefore also counts main Bash calls SINCE THE LAST DISPATCH (reset on `PreToolUse` Agent/Task/Workflow) and nudges once past `AIRULESET_MAIN_BASH_PER_DISPATCH` (default 20) with batch-or-dispatch instructions; that nudge RESETS the counter, so it is a periodic nudge and never a wall. The ticket's other candidate — counting `gh` calls per TURN — was refuted by the same measurement (687 of 687 main turns carried exactly ONE Bash call) and deliberately not built.
- **EXECUTION of settled, scoped code = Sonnet 5 (`model: "sonnet"`) at `high`/`xhigh`.** The `subagent-driven-development` implementer, the **autopilot-worker** (full-issue end-to-end), workflow execute/transform stages. Quality is held by HIGH effort + the judgment bookends, NOT by the model tier. Execution does NOT escalate to Fable — hardness lives in design/debug/review, not in typing settled code.
- **Purely MECHANICAL / READ-ONLY plumbing = Sonnet 5 (or Haiku for the most trivial) + `low`/`medium`.** File enumeration, log scraping, grep/locate sweeps, format-only edits, "where is X" lookups, status polling. Model tier cannot change the outcome of a lookup, and lighter models return it faster.
- **Redundancy is still waste, not rigor** — ground once + pass a digest, size fan-outs to residual uncertainty, batch per-item verifies (`claude-code-tooling.md`). Unchanged under every policy. A Fable stage NEVER re-reads what a cheap stage already digested.
- **Self-audit before a multi-agent dispatch: every Fable stage must map to a named HARD criterion above AND a gate-OPEN check — an all-Fable or casually-Fable fan-out is still the tiering MISS.** Most stages are Sonnet (execute) or Opus (judgment); Fable takes the genuinely hard judgment stages when the gate is open.

Applies to all rewordings and semantic equivalents — the intent: Opus 5 plans/reviews by default, Sonnet 5 executes the scoped code, cheap model for cheap work, and genuinely HARD judgment work escalates to Fable 5 AUTOMATICALLY but always through the budget gate — so the user gets Fable-grade output on the hard things without Fable ever again burning the limits down mid-work.

#### Opus 5 / Fable 5 behavior (primary + escalation)

- **Literalism**: does exactly what rules say. Precise wording → high compliance. Vague wording → unpredictable.
- **Reasons more, calls tools less**: when a tool must be used (e.g., `gh run view` for CI monitoring, `Playwright` for E2E verification), the rule must say so explicitly.
- **Adaptive thinking** (no fixed budget): longer reasoning per turn, fewer back-and-forth rounds.
- **Default effort `high`** on all surfaces incl. Claude Code (per docs.anthropic.com/effort — Opus 5 and Fable 5 both: "start with `high`, the default"). **The managed MAIN-session baseline is `high`** (`MANAGED_EFFORT_LEVEL` in airuleset.py, `xhigh` → `high` since #56, 2026-07-25) — the prior managed `xhigh` MAIN-session default was carried over from the Opus 4.7/4.8 era ("start with `xhigh` for coding and agentic use cases", the old guidance), and the current docs explicitly say to run a fresh effort sweep rather than reuse a setting carried over from an earlier model. The user can still raise it per session with `/effort` (e.g. `/effort xhigh`, `/effort ultracode`) whenever a session genuinely needs the depth. `xhigh` stays reserved for demanding coding/agentic work — the **autopilot-worker** implementing a ticket, and gated HARD-task escalations — never a blanket MAIN-session default. Under the ACTIVE policy: DISPATCHED judgment work (plan/design/review/hard-debug) runs Opus 5 at `xhigh` (`max` only for genuinely frontier Opus work — it overthinks structured tasks); EXECUTION runs Sonnet 5 at `high`/`xhigh`; mechanical/read-only stays `low`/`medium` on a light model; a gated HARD-task Fable escalation runs `xhigh`/`max`. Don't blanket-`xhigh` mechanical work. Changing effort mid-session discards the prompt-cache prefix (per docs) — pick a level at session start and hold it; don't hot-swap effort in a running session without a reason stronger than the cache-write cost.

#### Subagent behavior (smaller models)

- Follow rules less reliably — they need explicit "do X, not Y" instructions.
- Benefit more from hook-level enforcement (100% compliance regardless of model).
- Benefit from pattern lists (banned phrases, anti-patterns) — literalism matters less when the model already pattern-matches.

#### How to write rules for both

- **Lead with the rule in precise terms** — Opus 5 will follow it exactly.
- **Follow with anti-patterns / banned phrases** — helps subagents.
- **End with "applies to all rewordings and semantic equivalents"** — prevents 4.8 from taking bullet-point lists as exhaustive.
- **Critical enforcement goes in hooks**, not rules — works for every model.

#### Example

Bad (vague, subagent may miss): "Don't skip tests."
Good (precise + pattern + semantic gate):
> "NEVER use `#[ignore]`, `test.skip()`, or `pytest.mark.skip`. Any rewording or equivalent skip mechanism also applies."
