### Model Awareness (2026)

**The MAIN interactive session runs whatever the user set via `/model`** (their call alone — never auto-downtier it), **and the managed launch default on every box is Fable 5** (`claude-fable-5[1m]` — `MANAGED_MODEL`, user directive 2026-08-13). **Opus 5** (`claude-opus-5` — including the bare `opus` alias, which resolves to it on the Anthropic API) **is BANNED everywhere**: never as a main model, never a subagent dispatch, never a Workflow stage, never in settings or agent frontmatter (lock-tested — `tests/test_model_tiering.py`'s grep-gate). **Fable 5** (`fable`) is dispatched, through the budget gate, for every subagent task with REAL judgment/design content (the JUDGMENT-CONTENT test below) — and on the airuleset repo for EVERY substantive subagent dispatch (Fable-MAJORITY, owner directive 2026-08-25); **Opus 4.8** (`claude-opus-4-8`) is the routine-execution tier and the gate-CLOSED fallback; **Sonnet 5** (`sonnet`) carries LIGHT / mechanical work (CI polling, log scraping, grep/locate sweeps, status collection, format-only transforms, read-only lookups) — but **Sonnet 5 is never used for anything complex** (when in doubt, Opus 4.8); Haiku 4.5 (`haiku`) for the most trivial reads. **The main model is the user's deliberate call — NEVER recommend switching it, in either direction** (2026-07-31 precedent: the once-per-session "recommend Opus 5" line was already RETIRED then, and the 2026-08-13 ban settles the direction outright); the user's `/model` choice stays theirs alone. Rules must work for Fable AND the Opus 4.8/Sonnet/Haiku subagents. Tier/price tables, the benchmark citations and the full policy history live in the **`fable-advisor`** skill — load it when reasoning about tiers or costs.

#### Model tiering — Fable 5 for judgment-content work; airuleset subagents Fable-MAJORITY; Opus 4.8 routine fallback; Opus 5 BANNED (ACTIVE policy, 2026-08-25 — revises 2026-08-14 HARD-only)

*(This section is the GENERAL tiering policy. `claude-code-tooling.md` → "Tier the model PER STAGE" restates the same tiers as their Workflow-specific application (`opts.model`/`opts.effort` per `agent()` stage) — that overlap is INTENTIONAL, not a dedup target: general policy here, its Workflow application there.)*

No doteraz som nemal stym problem ze to ma taku spotrebu ta nastala asi az po dnesnych zmenach v pouzivani modelov."* The 2026-08-13 policy made a gated Fable dispatch the DEFAULT judgment layer; the 2026-08-14 refinement narrowed it to genuinely HARD (design-heavy) work only, with Opus 4.8 the default for execution AND ordinary judgment/review and Sonnet 5 rehabilitated for light/mechanical work ("moze byt aj sonnet 5 vyuzivany"). **REVISED (2026-08-25, verbatim):** *"ale ja by som chcel aby sa fable pouzival nie len na super tazke subagenticke ulohy, lebo som ho v principe nevidel zapnuteho za celu zivotnost vsetkych subdevs nikde subagenta s fable, chcem aby sa ta hranica posunula aby sa pouzival fable ovela viac, cize napr na 50% subagentickych uloh a plus tu na airuleset chcem aby sa majoritne pouzival fable lebo chyby ktotre tu robi opus mi extremne zeru cas a degraduju celu flotilu"* — the 2026-08-14 HARD-only boundary was, in practice, NEVER crossed (zero Fable subagents across the subdevs' whole lifetime: the taxonomy's height plus its always-against-Fable tie-break meant no dispatch ever qualified, while the budget gate sat OPEN the whole time), so the boundary MOVES: **Fable runs every subagent task with real judgment/design content** (the JUDGMENT-CONTENT test below — ≈ the owner's 50% target), **on the airuleset repo Fable is the MAJORITY subagent tier outright** (Opus mistakes there degrade the whole fleet), and **Opus 4.8 becomes the routine-execution fallback tier**. The MAIN session stays the user's Fable choice; Sonnet 5 light/mechanical work and the Opus 5 ban are UNCHANGED. Every automatic Fable dispatch stays BUDGET-GATED: `python3 ~/devel/airuleset/airuleset.py fable-gate` (exit 0 `OPEN` / exit 1 `CLOSED`) — the gate **guards EVERY automatic Fable dispatch** (the judgment-content tier + the airuleset Fable-majority), with its default threshold raised 80→90 (2026-08-25: at the observed baseline fable=43%/weekly=66% the new dispatch load projects into the 60–90% band, which an 80% gate would dead-letter mid-week — the last 10% stays reserved for the owner's own interactive Fable main). Gate CLOSED → the same work runs **Opus 4.8** (`claude-opus-4-8`) — never the `opus` alias, never Sonnet. Fail-safe: missing/stale cache = CLOSED, unchanged. (Why the gate exists: `fable-advisor` skill.)

**The lineup:**

- **Main interactive session = the user's `/model` choice; the managed launch default is Fable 5 (`claude-fable-5[1m]`).** Never auto-downtier it; never re-recommend against it.
- **JUDGMENT-CONTENT test — the fleet-wide Fable selector (2026-08-25).** A dispatch runs gated `model: "fable"` when the task carries REAL judgment or design content — the worker will make decisions that shape the result, not merely type settled changes. ANY of these qualifies: (a) **Non-trivial implementation** — the ticket needs design decisions (structure, approach choice, more than one defensible way to build it; anything whose design comment is more than a TRIVIAL one-paragraph). (b) **Review / verify of a non-trivial change** — the adversarial audit of any diff that itself carried judgment content; this includes, ALWAYS, the gatekeeper's review/verdict of a sub-dev hand-off (user directive 2026-07-24 — the tiering lives in the `process-subdev` skill). (c) **Hard debugging** — a root cause not obvious on first read, or a prior attempt failed. (d) **Plan / design / synthesis** of any feature or component. NOT judgment content (→ Opus 4.8): a genuinely mechanical scoped edit with one obvious shape (typo, rename, format fix, version bump, config value), executing an already-fully-settled plan with zero remaining decisions, review of a trivial diff. **Tie-break REVERSED: when unsure whether a task carries judgment content → it DOES** (the 2026-08-14 "unsure → it is NOT hard" tie-break is exactly what produced zero Fable dispatches). The owner's **≈50%** share of subagent tasks is the **calibration check, never a counter** — honest application of this test lands near half of subagent tasks on Fable, and a day of dispatches consistently far below that means the test is being applied too strictly. Protocol: run the gate ONCE per qualifying task/batch (not per subtask): OPEN → dispatch `model: "fable"` at `xhigh` (or `max` for the truly frontier); CLOSED → the SAME work runs **Opus 4.8** and you do NOT keep re-polling the gate within the task. Never skip the gate for an automatic Fable dispatch.
- **airuleset repo = Fable-MAJORITY subagent dispatch (2026-08-25).** In the airuleset repo every SUBSTANTIVE subagent dispatch — worker execution, review, validation-grade judgment — skips the judgment-content test and carries an explicit `model: "fable"` when the gate is OPEN (this repo's output steers every model on the fleet, so Opus mistakes here multiply — the owner's verbatim rationale above); gate CLOSED → dispatch WITHOUT the override so the frontmatter-pinned `claude-opus-4-8` runs (the fallback tier). Only genuinely mechanical/read-only dispatches (CI polls, log scrapes, lookups) stay `model: "sonnet"`/`"haiku"`, exactly as everywhere else.
- **HOW to reach Opus 4.8 (the gate-CLOSED fallback and routine-execution tier):** the per-dispatch `model` param takes only aliases (`sonnet|opus|haiku|fable`) and `opus` is banned — so Opus 4.8 is reached via (a) an agent DEFINITION whose frontmatter pins `model: claude-opus-4-8` (autopilot-worker, ticket-validator — full ids in frontmatter are documented AND live-verified: a probe agent resolved `claude-opus-4-8` in its own transcript), (b) a Workflow stage's `opts.model: 'claude-opus-4-8'` (full model names are legal there per the SDK docs), or (c) OMITTING the model override so the dispatch inherits a `claude-opus-4-8` parent (a worker's own sub-dispatches). A Fable MAIN session at gate CLOSED holds the judgment itself instead of spending a new gated dispatch — never the `opus` alias, never Sonnet for judgment.
- **DESIGN-HEAVY (HARD) taxonomy — a design-DEPTH classifier, no longer the Fable selector (2026-08-25; the JUDGMENT-CONTENT test above selects the model, and design-heavy is a strict SUBSET of it).** The autopilot skill's design-triage step still reuses exactly this taxonomy to pick which tickets get the fuller 2-3-approach design treatment and a supervisor-side `Plan` synthesis. A ticket/stage is design-heavy when ANY of these holds:
  1. **Architecture / design / synthesis of a genuinely COMPLEX or cross-cutting system or feature.** "Multi-file" alone is NOT the bar — most ordinary features touch several files; the bar is complexity/ambiguity of the design itself.
  2. **Hard debugging** — a root cause that resisted a first real attempt, or a multi-component / concurrency / heisenbug-class bug.
  3. **Adversarial final review / verify of a safety-critical or genuinely complex change** (keystroke-injection guards, auth, data-loss paths, gnarly concurrency) — including, ALWAYS, the sub-dev hand-off review above.
  4. **An autopilot ticket that is architectural / cross-cutting / ambiguous-design, or one a prior worker already failed on.**
  5. **The session is CIRCLING — ≥2 attempts at the SAME decision / plan / root cause without progress** (rework loops, try-A-fail-try-B-fail-try-A-again — the user's "točíme sa dokolečka" complaint, 2026-07-08). Do NOT run a third identical lap — ground the stuck problem into a digest and consult through the gate (advisor SHAPE below). The valve keys on **OBSERVED circling**, never on assuming the model is broken.
  Routine work is NOT design-heavy: scoped bug fixes, features with a settled design, execution of a settled plan, mechanical sweeps — those stay at the ordinary one-paragraph design-comment DEPTH (their MODEL is still picked by the judgment-content test above, whose tie-break runs the other way).
- **ROUTINE EXECUTION of settled, scoped code = Opus 4.8 (`claude-opus-4-8`) at `high`/`xhigh` — the fallback tier.** The `subagent-driven-development` implementer, the **autopilot-worker** (frontmatter-pinned), workflow execute/transform stages (`opts.model: 'claude-opus-4-8'`) — for work with NO real judgment content, and for every gate-CLOSED fallback. Sonnet no longer carries execution. Since 2026-08-25 execution is NOT categorically excluded from Fable: an implementation that carries judgment content (or any substantive airuleset dispatch) runs gated `model: "fable"` end-to-end — the old "hardness lives only in design/debug/review, never in the typing" reading is retired (it was half of why zero Fable subagents ever ran). A mid-ticket HARD wall on a 4.8 worker still dispatches a gated `model: "fable"` consult, then execution continues on Opus 4.8.
- **Purely MECHANICAL / READ-ONLY / LIGHT plumbing = Sonnet 5 (`model: "sonnet"`) or Opus 4.8 low.** This is the tier the 2026-08-14 refinement explicitly REHABILITATED ("moze byt aj sonnet 5 vyuzivany"): CI polling, log scraping, grep/locate sweeps, file enumeration, status collection, format-only transforms, "where is X" lookups — dispatch these on **`model: "sonnet"` + `low`** (Haiku for the most trivial reads). Where a surface can NAME the tier (a pinned agent definition, a Workflow stage's full-id `opts.model`), Opus 4.8 at `low`/`medium` is equally fine; on an ad-hoc alias-only dispatch (`Explore`/`general-purpose`), `model: "sonnet"` is the right EXPLICIT choice — never a model-less dispatch that would inherit the Fable main and put the MOST expensive tier on the cheapest work. Sonnet 5 is never used for anything complex — a sweep that carries any real judgment is judgment-content work and runs gated `fable` (Opus 4.8 at gate CLOSED); when in doubt between Sonnet and Opus 4.8 for a genuinely mechanical sweep, Opus 4.8.
- **HARD RULE — NEVER dispatch a subagent without an EXPLICIT model choice.** A `model`-less `Agent`/`Explore`/`general-purpose` dispatch INHERITS the caller's model — and since the managed MAIN default is Fable 5, a model-less dispatch from a Fable main silently runs the SUBAGENT on Fable, which is exactly the 2026-08-14 burn (live evidence: gk `general-purpose` CI-poll agents at 300–430k tokens EACH on inherited Fable, purely mechanical work; the 5h Fable limit gone in ~30 minutes). Every ad-hoc dispatch carries an explicit `model`: `sonnet`/`haiku` for mechanical/read-only/light, `fable` (gate OPEN) for judgment-content work and every substantive airuleset dispatch, or a `claude-opus-4-8`-pinned agent definition for routine execution and the gate-CLOSED fallback. EXPLICIT means a `model` param on the dispatch, OR an agent definition with pinned `model:` frontmatter (autopilot-worker, ticket-validator) — never inheritance from a Fable main. **TRAP (live gk incident 2026-08-14): the explicit-model requirement for the OPUS 4.8 tier is satisfied by the pinned agent frontmatter (`model: claude-opus-4-8`) or inheritance from a `claude-opus-4-8` parent — with NO `model` param at all. Passing `model: "opus"` is NEVER correct: the `opus` alias resolves to the BANNED Opus 5 (1M context) AND overrides the frontmatter pin — a gk main, told "every dispatch must carry an explicit model", passed `model: "opus"` and launched Opus 5 live before catching + re-dispatching without the override.** The only valid explicit `model` PARAMS are `"sonnet"`, `"haiku"`, or (gate OPEN) `"fable"`; the Opus 4.8 tier is reached WITHOUT a param. This is lock-tested — `tests/test_model_tiering.py`.
- **SHAPE — a Fable CONSULT = ADVISOR: digest in, decision out.** For a consult-style call (hard-debug advice, a design-fork verdict): a cheap stage grounds the problem into a TIGHT digest — facts, constraints, attempts already failed, the ONE concrete question; ONE Fable call returns the decision; execution applies it on Opus 4.8. A Fable consult never re-reads the repo wholesale, never fans out, and never runs mechanical plumbing. What the 2026-08-25 revision settles: **a DISPATCHED, fresh-context Fable worker is a sanctioned shape** — a gated `model: "fable"` dispatch (fresh, bounded context) carries any judgment-content task end-to-end, and every substantive airuleset dispatch; the 2026-08-14 "Fable never a worker / HARD-only" reading is retired. What stays BANNED is Fable as a long-lived MAIN implementation session (a Fable MAIN re-reads the full conversation context every turn — the 2026-07-01 burn; `block-main-implementation.sh` still hard-blocks implementation-size edits from a MAIN session with an ARMED `/goal` or one running unattended, #54) — the ADVISOR digest shape above stays the right form for a consult-style call.
- **Redundancy is still waste, not rigor** — ground once + pass a digest, size fan-outs to residual uncertainty, batch per-item verifies (`claude-code-tooling.md`). A Fable stage NEVER re-reads what a cheap stage already digested.
- **Self-audit before a multi-agent dispatch — the miss now runs BOTH ways:** every Fable stage must carry a gate-OPEN check (an ungated Fable fan-out, a Fable stage on genuinely mechanical plumbing, or a model-LESS dispatch that silently inherits the Fable main is still the tiering MISS) — AND routing a judgment-content task to Opus 4.8 out of the old HARD-only habit is EQUALLY a miss (the zero-Fable failure the 2026-08-25 directive corrects). Routine settled execution is Opus 4.8; mechanical/read-only/light stages are Sonnet 5 (or Haiku for the trivial); judgment-content stages — and every substantive airuleset stage — are gated Fable.

Applies to all rewordings and semantic equivalents — the intent: Fable 5 is the user's MAIN default at launch AND the gated tier for every subagent task with real judgment/design content (majority-of-subagents on the airuleset repo), Opus 4.8 is the routine-execution and gate-CLOSED fallback tier, Sonnet 5 carries light/mechanical work (never anything complex), Haiku the most trivial reads, no subagent is ever dispatched model-less from a Fable main, and the BANNED Opus 5 never runs anywhere, on any surface, under any alias.

#### Fable 5 / Opus 4.8 behavior

- **Literalism**: does exactly what rules say. Precise wording → high compliance. Vague wording → unpredictable.
- **Reasons more, calls tools less**: when a tool must be used (e.g., `gh run view` for CI monitoring, `Playwright` for E2E verification), the rule must say so explicitly.
- **Adaptive thinking** (no fixed budget): longer reasoning per turn, fewer back-and-forth rounds.
- **Effort:** the API default is `high` (per docs.anthropic.com/effort), but **the managed MAIN-session baseline is `xhigh` + standing ultracode** (`MANAGED_EFFORT_LEVEL` in airuleset.py + the launcher's `--settings '{"ultracode":true}'` — #445, user directive 2026-08-13, reversing #56/#53) — the user can still lower it per session with `/effort`. DISPATCHED judgment-content work (and every substantive airuleset dispatch) runs gated Fable at `xhigh` (`max` only for genuinely frontier work — it overthinks structured tasks); routine settled execution runs Opus 4.8 at `high`/`xhigh`; mechanical/read-only/light stays `low`/`medium` on Sonnet 5 or a light tier — don't blanket-`xhigh` mechanical dispatches. Changing effort mid-session discards the prompt-cache prefix (per docs) — pick a level at session start and hold it; don't hot-swap effort in a running session without a reason stronger than the cache-write cost.

#### Subagent behavior (smaller models)

- Follow rules less reliably — they need explicit "do X, not Y" instructions.
- Benefit more from hook-level enforcement (100% compliance regardless of model).
- Benefit from pattern lists (banned phrases, anti-patterns) — literalism matters less when the model already pattern-matches.

#### How to write rules for both

- **Lead with the rule in precise terms** — the top tiers will follow it exactly.
- **Follow with anti-patterns / banned phrases** — helps subagents.
- **End with "applies to all rewordings and semantic equivalents"** — prevents a smaller model from taking bullet-point lists as exhaustive.
- **Critical enforcement goes in hooks**, not rules — works for every model.

#### Example

Bad (vague, subagent may miss): "Don't skip tests."
Good (precise + pattern + semantic gate):
> "NEVER use `#[ignore]`, `test.skip()`, or `pytest.mark.skip`. Any rewording or equivalent skip mechanism also applies."
