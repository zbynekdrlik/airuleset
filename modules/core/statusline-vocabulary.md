### Statusline Vocabulary — "issues N" = the Footer Segment

**When the user says "issues N", "gk N", or "skipped N", they usually mean the airuleset statusline segment at the BOTTOM of Claude Code** (the footer next to the ctx meter) — not a GitHub query for you to invent (user directive, 2026-07-19). The segment's forms:

History + rationale — footer simplification rounds (#367/#512/#526), parked-segment consolidation, needs-acceptance state machine: `.claude/rules-reference/statusline-vocabulary-history.md` (#859).

The footer is exactly **5 segments — `I · U · W · gk · skip`** — plus the account-identity block: **`I`=Issues** (this box's own WORKABLE work), **`U`=User/you** (everything on the OWNER's court), **`W`=Wait/third-party** (an external event/evidence), **`gk`=gatekeeper** (handed off), **`skip`=skipped** (`autopilot-skip`). `needs-acceptance` routing: bare → `U` (queued for owner approval); `needs-acceptance`+`ops-wait` → `W` (sent, waiting on client); `needs-answer`/`needs-decision`+`ops-wait` → `U` (pending owner answer beats a sent thread). #507 precedence: a `needs-acceptance` ticket ALSO `ready-for-review`/`needs-gatekeeper` → `gk`, or `prio:bounce` → workable.

- `I N` (was `Issues N`) — the LIVE **workable** obligation-ticket count for this box (what THIS box must ACTION), always excluding `autopilot-skip` and `ops-channel` (#362, deliberately with NO bucket of its own — `.claude/rules/airuleset-internals.md` has the full rationale) AND the tickets PARKED on the OWNER (`needs-answer`/`needs-decision` since #468, and `needs-acceptance` since #512 — split by #526: a not-yet-sent acceptance goes to `U N`, a sent one carrying `ops-wait` to `W N`), which move to the `U N` bucket below — plus, since #510, `ops-wait` tickets parked on an external event/evidence, which move to the `W N` bucket — `I` counts Claude's responsibility, `U` counts the owner's (approve/answer), `W` counts a third party's: a full-authority (core/gatekeeper) box counts `core-quals` (the CORE partition unioned with every open `needs-gatekeeper`/`ready-for-review` ticket regardless of which stream owns it, since only this box can act on those — the exact set the `/goal` stop-proof already counts, never a parallel derivation, and here a handed-off ticket STAYS counted until actually closed — this box is the one that acts on it); a reduced-authority sub-dev box counts its own UNHANDLED work — `slice-quals`'s own slice (assigned ∪ authored ∪ stream-labeled tickets — or the stream label alone on a shared-gh-identity box) MINUS whatever is already parked with the gatekeeper (`len(mine) - gk`, #391, reversing the prior #367 "full slice, handed-off included" choice: once a sub-dev box has handed a ticket off, it is no longer THIS box's obligation, so the loop and the footer both stop counting it). A `gh` error renders nothing, never a wrong number. Deep I N▲ / gk counting detail: companion `skills/statusline-vocabulary-deep/DEEP-1.md` (#859).
- `· U N` (#468, consolidated by #512, refined by #526) — **`U` = only what Claude ASKS the OWNER / what the OWNER must APPROVE** ("čo sa ťa Claude pýta / čo máš schváliť"): open tickets in this box's scope carrying `needs-answer` (ask-and-continue's pinged marker), `needs-decision` (a decision explicitly deferred TO the owner — a generic owner-decision label, #791), or `needs-acceptance` **whose client acceptance thread has NOT yet been written+sent** (Claude must still get the owner to approve + send it — a genuine question on the owner; once the stream SENDS the thread and adds `ops-wait` it leaves `U` for `W`, #526) PLUS the unanswered session ❓ pings that carry NO ticket reference (the merged-in `Q`; a ping whose text references a `#N` ticket is already counted via that ticket's label, so it is NOT double-counted). They LEAVE `I N` (the owner's court to answer/decide/approve, not Claude's to solve — the 2026-08-14 directive "v I by nemali byť tie čo sú Q — nech je jasné kto za čo zodpoveda") and render orange-adjacent, hidden at 0, on BOTH scopes. A bare `needs-acceptance` (no `ops-wait`, no gk-override) is QUEUED for owner approval and ALWAYS belongs in `U` — NEVER dispatchable-now `I` code work (#622). Deep U state-machine mechanics (#526-#797): companion `skills/statusline-vocabulary-deep/DEEP-1.md` (#859).
- `· W N` (#510, extended by #526) — **`W` = SENT, waiting on a THIRD PARTY** ("odoslané, čaká tretia strana"): open tickets in this box's scope carrying the `ops-wait` label — an ADVISORY state the SUPERVISOR sets and clears itself with evidence (no auto-labelling), for a ticket that is open + technically "workable" but really blocked on an external event / evidence (multi-day evidence collection, a foreign-session relaunch, an operational confirmation) with NO dispatchable code lane — PLUS (since #526) a `needs-acceptance` ticket whose client acceptance thread has already been SENT: the stream adds `ops-wait` on send, and `_partition_workable`'s acceptance-scoped override routes a `needs-acceptance`+`ops-wait` row to `W` (tagged `acceptance` in `--ops-wait`, vs `ops-wait` for a pure ops-wait member) — it is now waiting on the CLIENT to confirm, not on the owner to approve+send. They LEAVE `I N` exactly like `U N`, but for a DIFFERENT parking reason (a third party, not the owner's answer); rendered grey (245, the exclusion-badge family — not this box's urgent workable), hidden at 0, on BOTH scopes. Deep W state-machine mechanics (#526-#818): companion `skills/statusline-vocabulary-deep/DEEP-2.md` (#859).
- `· gk N` — sub-dev boxes only: own tickets STILL awaiting the gatekeeper's action — shown SEPARATELY, no longer a subset of `I N` (#391: `I N` now EXCLUDES a handed-off ticket rather than including it, so `gk N` is the parked count next to it, not a slice carved out of it). Hidden at 0. Deep gk timeline-check mechanics (#589): companion `skills/statusline-vocabulary-deep/DEEP-1.md` (#859).
- `· skip K` (was `· skipped K`) — tickets labeled `autopilot-skip` (excluded from `I N`); hidden at 0.
- `disk NN%` (#834, narrowed #854) — the box's own disk-pressure reading, shown ONLY at **≥ 90 %** (red), **hidden < 90 %** so the footer stays quiet while a box oscillates 80-90 %; read from the machine-local `~/.claude/disk-guard/status.json` cache the watchdog Job 40 writes, and hidden when that cache is stale (> 10 min → a dead watchdog never paints a frozen %). It is the owner's ONLY surface for disk pressure (the guard's drain findings never ping Discord, #693/#704/#850).
- **`Q N` and `A N` no longer exist as segments** — folded into `U N` (#512); a user quoting "Q N" / "A N" means `U N`. The re-ask job is RETIRED (#795) — a ❓ is asked ONCE; the question map + `U N` badge hold it VISIBLE; the owner invokes processing himself via the "U N?" step-by-step flow. History + rationale: `.claude/rules-reference/statusline-vocabulary-history.md` (#859).
- `<email> sub <D.M.>(<Nd>)` — the account identity block, at the very end of the line, ONE unit (both properties of the same `~/.claude.json` → `oauthAccount`, so they belong together). `<email>` is `oauthAccount.emailAddress`, rendered in a readable colour. `sub <D.M.>(<Nd>)` is the monthly subscription-renewal anchor (`oauthAccount.subscriptionCreatedAt`, the next occurrence of that day-of-month), coloured by proximity (green far, yellow near, red on the last day).

**Width budget:** the whole line is fit inside the live tmux pane's width MINUS a reserve for Claude Code's own right-edge indicators (the armed-`◎ /goal` glyph is the live-evidence one — a fully-consumed pane once truncated the statusline clean off the end of the row, misread as "the goal died"). When it would overflow, the LEAST important segments are dropped dynamically, in this order: the account-identity block (email + sub) first, then the caveman tag, then — last resort — just the `ctx` segment's own `~$<cost>` suffix (keeping `ctx <size>` alone). An unmeasurable pane width (no live tmux pane, e.g. outside tmux entirely) never trims anything — the line always renders in full in that case.

The segment renders from a machine-local cache — read it when the user asks about it (never guess, never re-derive differently): `~/.claude/tickets-status/<cwd-key>.json` (refresh: `python3 ~/devel/airuleset/airuleset.py tickets-status --refresh --cwd <dir>`). A number the user quotes that mismatches your own `gh` count usually means a stale cache (TTL 120 s) or the per-stream scoping above — explain, don't dismiss. Applies to all rewordings ("v pätičke", "dole v claude", "ten counter").
