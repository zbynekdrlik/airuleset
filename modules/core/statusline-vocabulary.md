### Statusline Vocabulary — "issues N", "gk N", "skipped N" = the Footer Segment

**When the user says "issues N", "gk N", or "skipped N", they usually mean the airuleset statusline segment at the BOTTOM of Claude Code** (the footer next to the ctx meter) — not a GitHub query for you to invent (user directive, 2026-07-19). The segment's forms:

Every label was shortened on 2026-08-04 (#223 — dropped the ctx-fill bar, added the `sub`/account-email segments, and abbreviated every existing label so it all still fits on one line); the RENDERED forms below are current, the spoken forms above stay the natural way to refer to them. #313 (2026-08-08) simplified the footer further after a direct user rejection of #307's own wording ("chaos v cislach poctu ticketov") — see each bullet below for what changed.

- `I N` (was `Issues N`) — open non-`autopilot-skip`, non-`ops-channel` GitHub issues for THIS BOX's own slice, never automatically the whole repo: a full-authority (core/gatekeeper) box EXCLUDES every sub-dev stream's `stream:<user>`-labeled tickets (renders `I N core · str M` when the excluded population is known, so it never hides behind a bare number — #164); a reduced-authority sub-dev box counts only ITS OWN assigned/authored/stream-labeled slice. `ops-channel` (#362) is a stream's own self-declared PERMANENT channel — "this issue never auto-closes" (odoo-erp #1861/#3037: a teardown/refresh loop, a snapshot-retention alert log) — excluded from `I N`/`run N/T`, `core-quals`/`slice-quals` (the `/goal` stop-proof) and the Discord run-card's `remaining` count at the SAME tier as `autopilot-skip`; deliberately NOT its own visible bucket (no `· ops K`) — #313 already rejected adding more counters to this line, and a permanent, rare label would be exactly that noise. It stays invisible everywhere except this documented mention and `AUTOPILOT_SKIP_EXCL` in `airuleset.py`.
- `run N/T` (was `I D/T` / `Issues D/T`, then briefly `run N done` under #307) — an ACTIVE autopilot run: N = tickets carded this run, T = N + remaining, followed immediately by the SAME live `I N [core]` (+ `· str M` / `· gk M`) form the idle bullet above renders from the identical cache — never a combined ratio with `I`. `run` is a label DISTINCT from `I` on purpose (#307, 2026-08-07): the old `I D/T` form was textually and visually indistinguishable from the bare `I N` live-count form, and it never showed the core/streamy split — a real `I 41/103` was misread as "103 tickets on me" instead of a progress ratio whose total also carries historical growth. #313 (2026-08-08) brought the RATIO form back in place of #307's `run N done` wording — the user rejected "done" as strictly worse than the ratio ("to bolo 7/14 ovela lepsie a zrozumitelnejsie") — while keeping the `run`-vs-`I` label split #307 introduced it for. Green once the LIVE backlog is 0. Falls back to the same `run D/T` ratio only while the live open count is not yet known (a fresh cache, or a `gh` error).
- `· gk N` — sub-dev boxes only: own tickets already handed off to the gatekeeper. Hidden at 0 since #313 (was: "gk 0 still renders", #164 — reversed by direct user request, "nechapem na co vidim str 0"). The signal is the `ready-for-review`/`needs-gatekeeper` LABEL when present, falling back to a direct per-ticket check for a `READY-FOR-REVIEW:` comment when it is not (#313 pt 2 — a fork-no-merge collaborator's own label-add routinely 403s, and the repo's own auto-labelling workflow can independently be broken; the comment is the hand-off's real primary signal either way).
- `· str M` — full-authority boxes only: open non-skip tickets EXCLUDED from the `core` count because a sub-dev stream owns them (#164). Hidden at 0 since #313 (was "still renders at zero").
- `· skip K` (was `· skipped K`) — tickets labeled `autopilot-skip` (excluded from runs); hidden at 0.
- `· gkq N` (was `· gk-req N`) — full-authority boxes only: open `needs-gatekeeper` tickets = sub-dev streamy čakajú na akciu supervízora (airuleset #30; kanál `airuleset.py gk-request`, doručenie watchdog job 11); hidden at 0. (Nezamieňať so sub-dev `· gk N` = vlastné tickety odovzdané gatekeeperovi.)
- `Q N` (was `otazky N`, own chunk next to the `I` segment) — UNANSWERED ❓ pings awaiting the user's reply, SCOPED to the session's project, orange, hidden at 0. Source: the machine-local question map `~/.claude/discord-questions.json` (entry added per ❓ ping; dropped when the watchdog routes the Discord answer into the asking session, OR the moment the session gets a later HUMAN prompt — answered at the terminal; 24h TTL backstop). The cross-project `· inde M` form (pending questions in OTHER projects on this box) was REMOVED entirely in #313 (2026-08-08, direct user request: "na co ja potrebujem byt obtazovany ze niekde inde je otazka, ved to si mam riesit tam kde je ta otazka a nie tu" — the pending question already pinged the phone via Discord from ITS OWN project's footer; a second project repeating the count was noise, never actionable from there).
- `<email> sub <D.M.>(<Nd>)` — the account identity block, at the very end of the line, ONE unit (#313 pt 6 moved `sub` next to the email — both are properties of the same `~/.claude.json` → `oauthAccount`, so they belong together instead of scattered across the line). `<email>` is `oauthAccount.emailAddress`, now rendered in a READABLE colour (was near-invisible "faint"/dim — direct user complaint, "email je tak sivy ze je skoro necitatelny"). `sub <D.M.>(<Nd>)` is the monthly subscription-renewal anchor (`oauthAccount.subscriptionCreatedAt`, the next occurrence of that day-of-month), still coloured by proximity (green far, yellow near, red on the last day) — that part is unchanged.

**Width budget (#313 pt 4, 2026-08-08):** the whole line is fit inside the live tmux pane's width MINUS a reserve for Claude Code's own right-edge indicators (the armed-`◎ /goal` glyph is the live-evidence one — a 176-column pane fully consumed by the statusline once truncated it clean off the end of the row, twice misread by the user as "the goal died"). When it would overflow, the LEAST important segments are dropped dynamically, in this order: the account-identity block (email + sub) first, then the caveman tag, then — last resort — just the `ctx` segment's own `~$<cost>` suffix (keeping `ctx <size>` alone). An unmeasurable pane width (no live tmux pane, e.g. outside tmux entirely) never trims anything — the line always renders in full in that case.

The segment renders from machine-local caches — read THOSE when the user asks about it (never guess, never re-derive differently): `~/.claude/tickets-status/<cwd-key>.json` (refresh: `python3 ~/devel/airuleset/airuleset.py tickets-status --refresh --cwd <dir>`) and `~/.claude/autopilot-progress/<repo>.json`. A number the user quotes that mismatches your own `gh` count usually means a stale cache (TTL 120 s) or the per-stream scoping above — explain, don't dismiss. Applies to all rewordings ("v pätičke", "dole v claude", "ten counter").
