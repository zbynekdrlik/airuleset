### Statusline Vocabulary — "issues N" = the Footer Segment

**When the user says "issues N", "gk N", or "skipped N", they usually mean the airuleset statusline segment at the BOTTOM of Claude Code** (the footer next to the ctx meter) — not a GitHub query for you to invent (user directive, 2026-07-19). The segment's forms:

#367 (2026-08-11) is the THIRD footer simplification round: the user wants exactly ONE live, decreasing number — how many tickets this box still has left before everything is done. DROPPED entirely: the active-run progress ratio (fed by a SEPARATE `autopilot-progress` cache the footer no longer reads at all — that cache still exists for job 20), the `core` suffix, the needs-gatekeeper repo-wide badge (already folded into the obligation set `I N` counts below, so it was pure duplicate decoration), and the excluded-from-core badge. KEPT unchanged: `· skip K`, `Q N`, the account-identity block, the width budget. Full pre-#367 history + rationale for every dropped form: `.claude/rules/airuleset-internals.md`.

- `I N` (was `Issues N`) — the LIVE obligation-ticket count for this box, always excluding `autopilot-skip` and `ops-channel` (#362, deliberately with NO bucket of its own — `.claude/rules/airuleset-internals.md` has the full rationale): a full-authority (core/gatekeeper) box counts `core-quals` (the CORE partition unioned with every open `needs-gatekeeper`/`ready-for-review` ticket regardless of which stream owns it, since only this box can act on those — the exact set the `/goal` stop-proof already counts, never a parallel derivation); a reduced-authority sub-dev box counts ONLY `slice-quals` (its own assigned ∪ authored ∪ stream-labeled tickets — or the stream label alone on a shared-gh-identity box). A `gh` error renders nothing, never a wrong number.
- `· gk N` — sub-dev boxes only: own tickets already handed off to the gatekeeper (a SUBSET of `I N`, never subtracted out of it — just naming which slice is already parked). Hidden at 0. The signal is the `ready-for-review`/`needs-gatekeeper` LABEL when present, falling back to a direct per-ticket check for a `READY-FOR-REVIEW:` comment when it is not (a fork-no-merge collaborator's own label-add routinely 403s, and the repo's own auto-labelling workflow can independently be broken — the comment is the hand-off's real primary signal either way).
- `· skip K` (was `· skipped K`) — tickets labeled `autopilot-skip` (excluded from `I N`); hidden at 0.
- `Q N` (was `otazky N`) — UNANSWERED ❓ pings awaiting the user's reply, SCOPED to the session's project, orange, hidden at 0. Source: the machine-local question map `~/.claude/discord-questions.json` (entry added per ❓ ping; dropped when the watchdog routes the Discord answer into the asking session, OR the moment the session gets a later HUMAN prompt — answered at the terminal; 24h TTL backstop).
- `<email> sub <D.M.>(<Nd>)` — the account identity block, at the very end of the line, ONE unit (both properties of the same `~/.claude.json` → `oauthAccount`, so they belong together). `<email>` is `oauthAccount.emailAddress`, rendered in a readable colour. `sub <D.M.>(<Nd>)` is the monthly subscription-renewal anchor (`oauthAccount.subscriptionCreatedAt`, the next occurrence of that day-of-month), coloured by proximity (green far, yellow near, red on the last day).

**Width budget:** the whole line is fit inside the live tmux pane's width MINUS a reserve for Claude Code's own right-edge indicators (the armed-`◎ /goal` glyph is the live-evidence one — a fully-consumed pane once truncated the statusline clean off the end of the row, misread as "the goal died"). When it would overflow, the LEAST important segments are dropped dynamically, in this order: the account-identity block (email + sub) first, then the caveman tag, then — last resort — just the `ctx` segment's own `~$<cost>` suffix (keeping `ctx <size>` alone). An unmeasurable pane width (no live tmux pane, e.g. outside tmux entirely) never trims anything — the line always renders in full in that case.

The segment renders from a machine-local cache — read it when the user asks about it (never guess, never re-derive differently): `~/.claude/tickets-status/<cwd-key>.json` (refresh: `python3 ~/devel/airuleset/airuleset.py tickets-status --refresh --cwd <dir>`). A number the user quotes that mismatches your own `gh` count usually means a stale cache (TTL 120 s) or the per-stream scoping above — explain, don't dismiss. Applies to all rewordings ("v pätičke", "dole v claude", "ten counter").
