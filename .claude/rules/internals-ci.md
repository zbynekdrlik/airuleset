### airuleset internals — CI (`.github/workflows/`)

The repo's first GitHub Actions workflow landed in #683 (before that, `gh run list` was `[]` and the fleet-wide "main CI green" proof was unsatisfiable). CI mirrors the local integration gate: **ruff → `scripts/size_ratchet.py --check` → hermetic pytest subset → collected-count guard**, in a pinned `container: python:3.12`. No `continue-on-error` anywhere.

- **CI runs in `container: python:3.12`, NOT `ubuntu-latest` — on purpose.** Hermeticity is only meaningful if the CI env is reproducible AND matches where "which tests are hermetic" was measured. `python:3.12` has no tmux (tmux-dependent tests fail deterministically, not flakily), a fixed toolchain, and the hermetic subset was measured inside exactly this image via `docker run python:3.12` on a fresh clone (== `actions/checkout`). So a local `docker python:3.12` run IS the CI env — the authoritative pre-merge proof (`refs/autopilot-wip/*` never triggers a workflow; the `pull_request` trigger DOES give a real pre-merge run on a dev→main PR, but a fleet worktree branch is often merged without a PR, so the local docker run + actionlint + `workflow_dispatch` are what a worker leans on before integration).
- **`jq` is the one CI-env install the hooks-under-test need.** ~95% of airuleset's hook scripts parse their payload with `jq` (`jq -r '.tool_input.command'`). `python:3.12` has NO jq, so WITHOUT it those hooks silently exit 0 (empty output) and ~924 hook tests fail with `AssertionError: 0 != 2 / '...' not found in ''`. `apt-get install -y jq` fixes 913 of them. (`ubuntu-latest` pre-installs jq — a reason the container needs an explicit step the runner would not.)
- **The suite is ~95% hermetic; the box-bound tail is 11 scattered tests + 2 collection-error files** (measured 2026-08-25, `python:3.12`+jq, uid 0): 9604 pass / 21 pre-existing skips / 0 fail after exclusion, 9625 collected. The exclusions are DATA in `.github/box-bound-tests.txt`, turned into pytest args by `scripts/ci_pytest_args.py` (a bare file path → `--ignore`; a node-id containing `::` → `--deselect`). It is a DENY-list on purpose — new hermetic tests run automatically, a new box-bound test surfaces as an honest failure that forces classification. `tests/test_ci_workflow_683.py` locks that every deny-list path still exists (no rot) + no continue-on-error + all gates wired.
- **Box-bound categories (why each of the 13 is excluded):** (a) files that raise `RuntimeError: tmux not found` at COLLECTION → must be `--ignore`d, not `--deselect`d (a collection error aborts the whole run): `test_webterm_ctrlbw_darkening.py`, `test_webterm_stream_footer_672.py`; (b) tests spawning a real tmux pane / reading a live session transcript (`TestClaudeHistoryPopupScript` ×3, `test_send_verified_adoption` transcript, `TestSessionStartFetchHook`); (c) `TestBurnSnapshotJob::test_failure_never_raises` (subprocess/env); (d) **ROOT-user artifacts** — the container runs as uid 0, so `sudo`/passwordless-sudo probes and `is_dir()` EACCES semantics differ from a normal user (`test_owner_key_provisioning` ×3, `test_count_live_workers` ×2). If CI ever moves to a non-root user, the 5 root-artifact tests would pass and could leave the deny-list.
- **How to re-measure after big test churn** (whenever CI's first main run fails on a NEW box-bound test): `docker run --rm -v <repo>:/src:ro python:3.12 bash -c 'apt-get update -qq && apt-get install -y -qq jq && git config --global --add safe.directory "*" && git clone -q /src /repo && cd /repo && pip install -q pytest ruff pytest-xdist && python -m pytest tests/ --ignore=<collection-error-files> -n 8 --dist=loadfile -q --junitxml=/out/j.xml'`, then classify per failing node-id and add genuinely box-bound ones to `.github/box-bound-tests.txt` (per-node, never whole files — the failures scatter inside otherwise-hermetic files; denying whole files would drop ~1340 hermetic tests). **`-n 8 --dist=loadfile` (xdist) is a MEASUREMENT-SPEED optimization ONLY — the actual CI job runs SERIAL (one process). `--dist=loadfile` gives each file a fresh worker process, so it can HIDE cross-file module-state leakage that a serial run surfaces. So after building the deny-list, run the EXACT CI command ONCE — serial, no xdist: `… && python -m pytest tests/ $(python3 scripts/ci_pytest_args.py .github/box-bound-tests.txt | tr '\n' ' ') -p no:cacheprovider -q` — and confirm it is green before trusting it.** (#683 was verified this way: a clean checkout of the branch, serial, 9621 passed / 0 failed.)
- **No-op-job guard:** `scripts/ci_assert_collected.py junit.xml <floor>` fails if the run collected below `floor` (5000, well under the real ~9625) — a mis-globbed deny-list that swallows the suite cannot masquerade as a green no-op (test-strictness.md). `tests/test_ci_assert_collected.py` is its RED-before-GREEN lock.
- **Tool versions pinned in CI:** `pytest==8.3.2 ruff==0.16.2` (match the box). Ruff's rule selection is pinned in `pyproject.toml` (`select = E4,E7,E9,F`) so `ruff check .` means the same thing regardless of ruff version (#429).
