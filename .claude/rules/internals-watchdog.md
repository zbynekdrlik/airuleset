FOUR reusable points. (1) **Consult the gate ONLY when there is a real measurement** (skip fork-skip / fetch-error / `st is None` / `counts is None`) — observing "neither healthy nor unhealthy" must NOT advance the episode; a fork-skip leaves the episode open (age-reaped at 30d), never sends a spurious recovery. (3) **Send-layer `dedup_key` is FRESH per instant (`int(now)`, the #535/#543 gk_request pattern), NEVER a coarser bucket** — the primary dedup is episode_gate (open once + recover once per episode); a bucketed send key would let notify's 14d TTL swallow a genuine re-open of a NEW episode. (4) **The round-robin batch + episode_gate compose safely by construction**: a repo out of the batch isn't measured → gate never called for it → its episode is UNTOUCHED (episode_gate only writes keys it is called with); a persistently-unhealthy repo measured every ~14h refreshes `last_seen` (< `EPISODE_MAX_AGE_S`=30d) so its open episode is never age-reaped prematurely.
