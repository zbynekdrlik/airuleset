### airuleset internals — skills / modules / agents / profiles / rules

Hlbší archív airuleset-internals je v `.claude/rules-reference/internals-archive.md` (on-demand). NOVÉ skills / modules / agents / profiles / rules lekcie pridávaj SEM.

- Every module must be standalone, actionable, and 5-20 lines
- Rules must have YAML `paths:` frontmatter
- Skills use the SKILL.md format with YAML frontmatter
- **Skills deploy per box (`skill_names_for_user()`): when scoping a skill away from a box, check whether that box's WORKFLOW actually uses it** — `SKILLS_EXTRA_BY_USER` re-grants a scoped-away skill per user (montalu ← meeting-analysis, 2026-07-14). And a skill deployed to isolated sub-dev users must be user-agnostic: `$HOME` paths, never `/home/newlevel/...`; per-user secrets read from `~/.claude/secrets/*.env` (provisioned via ssh-stdin, NEVER git).
### Which surface actually LOADS — measure before converting a module (#104, 2026-07-27)

Every `module → skill` or `module → path-scoped rule` conversion in this repo is
a bet that the target surface is loaded on the path that needs it. `e9d1022` lost
that bet once already, and the loss was invisible for 18 days. Before converting
anything, know these EMPIRICAL facts (three introspection probes, 2026-07-27 —
each subagent was asked only to report its own context):

| Surface | Reaches a dispatched subagent? |
|---|---|
| Global `~/.claude/CLAUDE.md` with `@import`ed module BODIES expanded | **YES** — probes quoted verbatim sentences from inside the modules |
| Project `CLAUDE.md` | **YES** |
| Auto-memory `MEMORY.md` | **YES** |
| An agent file (`agents/<name>.md`) | **YES** — it IS the subagent's system prompt |
| **Skill BODIES (`skills/*/SKILL.md`)** | **NO** — only the name + one-line description from the skill list |
| Path-scoped rules (`rules/*.md` → `~/.claude/rules/`) — MAIN session | **YES** — `nested_memory` attachment on Read (#105) |
| Path-scoped rules (`rules/*.md` → `~/.claude/rules/`) — dispatched SUBAGENT | **NO** — zero `nested_memory` attachments even with the correct cwd (#105) |

- **Durability-backup push of a worktree worker's branch (#503) — four reusable sub-lessons.** The worker builds work as LOCAL commits and (contract) never pushes to the integration flow; the supervisor merges from the local branch ref, so origin is unwritten until integration — the account-cap-death window. Fix = a CI-neutral BACKUP push after each commit. (1) **A push to any git ref OUTSIDE `refs/heads/*` and `refs/tags/*` (e.g. `refs/autopilot-wip/<branch>`) triggers NO GitHub Actions workflow on any GitHub repo, whatever its push-trigger config** (GitHub's `push`/`create`/`delete` events fire only for branches+tags — verified GitHub docs + community #48858). So a durable backup to a custom ref namespace burns ZERO CI with no per-repo reasoning and no branch-ignore edit — reuse this for any "durable copy on origin without burning CI" need. (2) **A `git push` hook exemption MUST anchor on the push DESTINATION refspec (`:refs/x/` or `--delete`/`-d refs/x/`), NEVER a bare `grep -q 'refs/x/'` over the whole command** — a bare substring false-exempts a real push that merely MENTIONS the ref in a commit message / echo / trailing comment, silently skipping the local gates (both #503 adversarial reviews reproduced this). (3) **When adding a `git push` gate/exemption, enumerate ALL FOUR push-gating hooks: `pre-push-lint.sh`, `pre-push-test-check.sh`, `pre-push-base-sync.sh`, `block-test-skips.sh`** — a review caught `block-test-skips.sh` missed from a 3-of-4 enumeration. Content-lock teeth caveat (extends #498/#500): a bullet that names a token TWICE (an authority name in both a coverage clause and a delivery clause) gives a partial revert NO teeth — lock a UNIQUE operative phrase ("regardless of authority"), not the recurring name.
