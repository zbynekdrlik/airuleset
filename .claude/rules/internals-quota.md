### airuleset internals — per-user quota on shared-stream boxes (#950 / #1140)

- **Three root writers share ONE limits renderer and ONE lock.** `_render_quota_limits_block()` is the only copy of the ceiling math. The push apply (`_render_quota_apply_block`), the daily `airuleset-quota-refresh` (recount + limits) and the hourly `airuleset-quota-ceiling` (limits ONLY, #1140 D) all embed it, and all take `QUOTA_LOCK_PATH` on fd 9 (busy → exit 4, touch nothing). The two scripts share `_render_quota_script_preamble()`. A second copy of the math is a test failure (`test_limits_math_exists_exactly_once_in_source`).
- **Ceiling formula (#1140 D, #1315):** `hard = min(max(10G, used*1.2), used + 50% of df avail on / / N)`, `soft = min(max(8G, used*1.1), hard)`, N = the shared-stream homes. Without the `/ N` every account was promised half the free space (subdev 13.11.: ~110G promised on 14G free, disk 95 %, no account at its quota), so the sum of the ceilings must fit the disk. The fs cap is floored at 1 KiB because setquota reads 0 as NO limit. An unreadable df is LOUD, sets `qfail` and still applies the unbounded formula, because a stale lower ceiling is the EDQUOT incident itself.
- **Bash on external numbers under `set -euo pipefail`:** parse df STDOUT only (a stderr warning merged with `2>&1` can void the value), force base 10 with `$(( 10#$x ))` (a leading `0` is octal: `08` errors), and guard non-numeric repquota fields with `${x//[0-9]/}` before any arithmetic. Otherwise one bad row aborts the whole user loop, and the read-back then "verifies" the OLD limits.
- **Execution tests must stub `df`.** The limits block reads the real fs size, so a test without a `df` stub depends on the box (a 16 GB-free box caps a 10G floor down to 9G). `test_quota_fix_forward_950._make_stubs` defaults one (1 TiB free). For a realistic read-back, use STATEFUL stubs (setquota writes, repquota reads back), as in `test_quota_ceiling_hourly_1140.py`.
- **Timer collisions:** `hourly` and `daily` both elapse at 00:00. The ceiling service is `After=airuleset-quota-refresh.service`, so systemd queues it behind the refresh instead of racing the lock.
- **[Moved to `.claude/rules-reference/internals-archive.md` at the #1137 mode / session-scope removal, 2026-10-25 — grep "Per-SESSION memory scope on workstations (#1224" there]** the machinery it describes is removed.
- **A guard keyed on a session id must key on the FILE, never the bare id (#1224 slice 2).** The id is also in the session's scratchpad (`/tmp/claude-<uid>/<proj>/<id>/scratchpad`), task-output and `tool-results` paths. A bare-id match would have blocked every ordinary scratch read, including the session that shipped it. `gates/owntranscript.py` triggers on `<id>.jsonl` or `.claude/projects`. It refuses any reader of a `*.jsonl` there, by path or glob, and any recursive read (`-r`, `rg`). It scans every `$(…)`/backtick body as its own command, but never splits on a bare paren, so `python -c 'open("x.jsonl")'` stays one command. Two more rules:
  - **"Bounded" head/tail means one numeric `-n <= 50` or `-c <= 64 KiB`.** `tail -n +1` and `tail -f` read everything.
  - **A hook test's PATH shim must use builtins only.** A `touch` missing from the isolated PATH silently recorded nothing. The root cause is fixed by `airuleset.py question-block`, which prints the last ❓ block from `discord-questions.json`. Declare a leaf subcommand's options on its subparser: `argparse.REMAINDER` drops a leading `--opt`.
  - **Only a content READER reads (live false positive, 0.1.538).** The first deploy blocked the ticket's own evidence comment. The shell text `cat > c.md <<EOF` held markdown that quoted a `grep … .jsonl` in backticks, and a `gh --body`, `git commit -m` or `echo` naming such a path was blocked too. The guard now looks only at a `READERS` head. It blanks heredoc bodies with `gates.selfservice._capture_heredocs`, except when an interpreter runs them (`python3 - <<EOF`, the songplayer shape). A guard that inspects shell TEXT must test documentation-shaped commands that MENTION its target, not only commands that use it. Also run `test_hook_runner_env_lock_1046` for any new hook test, which needs `hermetic_hook_env(self)`: Pass A refused the first 0.1.538 push on it.
- **#1395 — before writing a rewriter for Claude Code data, grep the binary for its OWN one; drive it ISOLATED and prove it ran; and scope a shell-text guard DOWN, not wider.** Claude Code 2.1.330 ships `performCompactTranscript` (per-type keep policy, copies rows appended during the rewrite, aborts on a source change, atomic rename). It runs in a NON-interactive session with `CLAUDE_CODE_TRANSCRIPT_LOCAL_GC=1` when a `/compact` completes, above 5 MiB; a plain `claude -c -p` with the env does NOT compact. A hand-built planner dropped kept-forever types and lost appends (2 reviews). `session-shrink` wraps it: `claude --resume <id> -p /compact --settings '{"disableAllHooks":true}' --strict-mcp-config --mcp-config '{"mcpServers":{}}' --tools "" --model claude-sonnet-5-5`, every `CLAUDE*` env var dropped, in the recorded cwd whose `[^A-Za-z0-9]`->`-` form IS the `projects/<dir>` name. Without the isolation an armed `/goal` loops and project hooks/MCP start (a plain resume of the probe wrote 3 hook lines + 1 MCP start; the isolated one 0). Success = a NEW boundary uuid + a smaller file (any old boundary passes a no-op). Guard: three review rounds broke every widening of the #1224 text parser, so it keeps main's rules plus a count/locate list and a BYTE-bound last stage (`| head -c`, `wc`, `grep -c`), with the known bypasses listed as accepted residuals. A recursive grep is a projects read only when a PATH operand is under `.claude/projects` (a code search for the string is not). Find such code with `strings -n 30 <binary> | grep -E <names>` into a scratch file, then python `str.find`: `grep -o ".\{0,600\}x"` on a 380 MB binary runs for minutes.

### disk-guard root — logrotate ownership (#1244)

- **A root apply that writes a logrotate stanza must ask the box who else rotates that log.** On gk, odoo-erp's `gk-auth` and airuleset's #841 btmp/wtmp files named the same logs, and logrotate failed nightly with `duplicate log entry`. `cli_logrotate_owner.DETECTOR_PY` is ONE source string: the box runs it (`python3 -I -`; `-I` because the sudo leg runs as root from the account's home) and the tests `exec` it. It parses PATH LINES only. When another file owns the log, airuleset's own file (marker on line 1) becomes a yield note, and a foreign file is never touched.
- **Mirror logrotate by MEASURING it, never from memory.** Run `logrotate --debug -s <state> <conf>` on a scratch include dir. 3.21 skips `*.bak` (a review 🔴: a yield to an ignored `btmp.bak` left btmp rotated by nobody). As root it also skips non-root-owned and group/other-writable files. A non-root `--debug` never "considers" a stanza with `su root root`, which is an artifact, so verify those as root read-only on the box.
- **The read-back must work in BOTH directions** (`build_logrotate_readback`): no duplicate entry, AND `considering log <log>` for every managed log. Use a bash `case`, never `| grep -q`, which SIGPIPEs the producer under `pipefail` (#1223).

### stream slice caps (#1321)

- **A managed systemd drop-in can lose to a foreign one that sorts later, and a read-back right after `set-property` cannot see it.** subdev's hand-made gatekeeper `user-.slice.d/50-fairness.conf` (8.8.2026) sorted after `50-airuleset-resource-guard.conf`, so every later `daemon-reload` restored CPUQuota 300 %, CPUWeight 100, TasksMax 8192: the managed CPU/task caps were never live, while the apply's verify (taken right after the runtime `set-property`) reported them as applied. Check `systemctl show -p DropInPaths user-<uid>.slice` for foreign files before trusting a verify. The apply now removes that file by its line-1 marker (`cli_resource_guards_conflicts.py`, backup in /root). Size a per-slice cap from `memory.peak`, `memory.events high` and `pids.peak` of the busiest stream, not from the box total: 12 % (~1.9 GB) sat below one Claude session with subagents.

### fail2ban hardening precedence (#1306)

- **A `jail.d/*.conf` loses to any hand-made `jail.local`.** fail2ban reads jail.conf → jail.d/*.conf → jail.local → jail.d/*.local. subdev's jail.local overrode the #841 `[DEFAULT] ignoreip`, so the controller got banned 3× on 16.11. The managed fix is `jail.d/50-airuleset-hardening.local` (`cli_fail2ban`). It appends PER JAIL with `ignoreip = %(known/ignoreip)s …`, which keeps the hand-made entries. Never put `known/` in `[DEFAULT]`: fail2ban 1.0.2 then refuses the WHOLE config ("Recursion limit exceeded").
- **Measure fail2ban precedence offline, never from memory.** Copy `/etc/fail2ban` to a scratch dir, add the candidate files, run `fail2ban-client -c <dir> -d | grep addignoreip` (the effective per-jail list). `-c <dir> -t` exits 255 on a refused config.
- **The apply runs `-t` before `reload`.** A refused config removes the .local and fails the apply. The read-back requires the tailnet CIDR in the RUNNING `fail2ban-client get sshd ignoreip`, because deployed ≠ effective.

### sshd MaxStartups drop-in (#1349)

- **OpenSSH 9.6 keeps the LAST `MaxStartups` it reads but the FIRST `PerSourceMaxStartups` (measured with `sshd -T` on two lines, 19.11.).** The first rollout assumed first-wins, named the file `50-`, and lost on gk to a hand-made `60-airuleset-maxstartups.conf` (30:30:150, #358); the live read-back caught it. The file is now `90-` and retires our own marked `50-`. Never assume one sshd directive's precedence from another: test the pair. The read-back therefore compares the value `sshd -T` resolves (root only: a non-root `sshd -T` prints nothing). `sshd -T` parses the files, not the running daemon, so a sha256 stamp in `/run/airuleset` records what the daemon last reloaded: an unchanged file whose earlier reload failed reloads again (review 🟡).
- **Validate, then reload only on change.** `cli_sshd_maxstartups` writes through `_install`, which sets `DGROOT_WROTE` when it really replaced a file. `sshd -t` gates the reload; a refused config this run wrote is removed and fails the leg, one a foreign file broke fails the leg and leaves ours alone. A full-apply harness (`test_disk_guard_root_apply_1223`) stubs every system tool the script calls, so a new tool in the apply needs a new stub there.
- **#1355 — the controller is outside the #841 root fan-out, so its root config is a LOCAL `cmd_install` provisioner (`cli_controller_journal`, journald `SystemMaxUse=1G`).** Idempotence on file BYTES alone hides a failed `try-restart`: the cap sits on disk but is never live, and every later install says `unchanged`. So compare journald's `ActiveEnterTimestamp --timestamp=unix` with the drop-in mtime and re-restart + rotate when journald is older. Same ticket: the daily `sweep_claude_scratch` now consumes the live-session `stale_children` (`cli_scratch_children`), not only the >= 80 % drain. A scripted `str.replace` on a multi-line block that recurs in the same file (`discovery error` + `for c in candidates:` exists in BOTH the scratch and transcript sweeps) edits every site: assert `s.count(old) == 1` first.

### fleetbackup read-only ACLs on subdev (#1387)

- **A named-ACL traversal grant opens every sibling through ACL_OTHER, and a named `---` on each sibling is not enough.** A file rewritten as temp file + rename is a NEW inode with no entry. systemd `--user` units run with UMask 0022 whatever the shell umask (watchdog state every 60 s, `git config`, `settings.json`, shell history), so those names were readable almost all the time. Two reviews reproduced it. Fix: a default `d:u:<x>:---,d:g::---,d:o::---` on every traversed dir, so new children are born closed. Pre-create the granted subtrees: a file born under the closed default has mask `---`, and a `-n` grant can never open it.
- **A recalculating `setfacl -m u:x:r-x` widens.** On a dir whose owner ran `chmod 700` after an ACL existed, it restores group rwx (measured). In the same call, set `g::---` on granted trees and `g::<effective>` on traversal dirs. Refuse a dir that carries any other named entry.
- **Root may only add a deny, `setfacl -P -n -m u:x:---`.** `-P` skips a symlink argument even without `-R` (acl 2.3.2, measured). Grants run as the account (`runuser -u <u> -- env -i …`).
- **`rrsync -ro` is not a jail.** It accepts `--copy-unsafe-links`, and it never checks the NAMES a `--files-from` list sends; the sender follows a symlink in the middle of each name. Both served `/etc` through a symlink planted in a granted tree. The forced command is an ALLOW-list wrapper: only `rsync --server --sender`, options minus the refused ones, `.`, and paths inside the granted trees. Test it with the real rsync + rrsync through a fake ssh that sets `SSH_ORIGINAL_COMMAND`.
- **A wrapper must split exactly like the program behind it.** rrsync 3.2.7 splits with Python `\s` (also VT, FF, CR, 0x1c-0x1f, NBSP) and honours backslashes; sh splits on space, tab and newline only. A VT between two words was one allowed option to the wrapper and `--files-from=-` to rrsync (round 3, served /etc through sshd). So refuse every byte outside `[A-Za-z0-9 ._/=,:+-]` BEFORE splitting, under `LC_ALL=C`: sshd's default `AcceptEnv LANG LC_*` lets the client choose the locale.
- **A shared login must never be withdrawn for a HOME-level fault.** Four review rounds each found a tenant-triggerable withdrawal: refuse/stall its own run, fill its xattr space, flip its ACL between root's deny and the read-back, a FUSE mount root cannot even `stat` (EACCES, so `find` fails and `! -user X` is true), a second account's child with full xattrs. The way out was an invariant, not a better classifier: every grant runs as the account, so every inode carrying our grant is the account's own, and whatever root cannot close there is open by the account's own doing or through "other" bits anyone has. So a home-level fault closes that home (root's deny) and fails it; only a BOX-level fault (a missing tool, fleetbackup's identity) withdraws. List `/home` by a glob (no per-entry stat, no temp file).
- **Withdrawal mechanics:** `chage -E 2` (our own value; `1` is the admin's documented lock) only when no expiry is set, the marker holding it written FIRST (a crash after it leaves a harmless marker, after `chage` an unliftable lock), key removal (only when the key dir is root-owned), then a read-back; the key also carries `expiry-time="…Z"`. A restore lifts only `2` with the marker, forgets a stale marker, and fails while an expiry that has passed remains.
- **Root an rrsync at the narrowest dir, and know it is still racy.** rrsync only checks that a path resolves inside its root: rooted at `/home`, `carol/uploads -> /home/bob/uploads` served bob's tree. The wrapper requires one account per pull, strips the prefix and runs `rrsync -ro /home/<account>`. rrsync checks `realpath` and rsync opens the path later, and rrsync re-resolves its root by name, so a tenant that swaps its tree root with `renameat2(RENAME_EXCHANGE)` still wins ~26 % of pulls (round 5): only a separate identity per account closes it in the kernel. Keep fleet-backup's discovery (`--list-only` of `./` alone) working at the `/home` root; it names no tree.
- **A default ACL beats the umask of ANYONE who writes into the dir.** `d:u:fb:r-x` on a tree dir an account opened for writing gave fleetbackup another user's umask-077 file (round 5). Root denies every inode in the trees the account does not own (pruned, batched), the read-back checks them as closed children, and the account side walks only its own inodes (`! -user <me> -prune`). Name the account by its home's owner, not `id -un`: a stub `runuser` under the CI container's root cannot switch users.
- **Bound every refresh, root's own work included.** A push queues the hourly unit (`systemctl start --no-block`, as the #1140 recount does) instead of walking every tree in its 180 s ssh call. The refresh has a budget: past it, the remaining homes are closed by root and the key is still renewed. Checks, account-side runs, root's record walks and root's deny of foreign children (ONE batched `xargs setfacl`, not one fork per child) are cut to it, never below 1 s: `timeout 0` means NO limit. Account output goes to a FILE under `ulimit -f`; bash reports a SIGXFSZ kill INTO that capped file, so the writing shell itself dies (stub with `{ …; } 2>/dev/null`). A bash `read -d ''` loop read 1.7 MB/s: the read-back is a python `os.access` loop.
- **Lock files root-only.** A world-readable lock file can be `flock`-ed by any user, which stalls every writer (the quota lock had it too). Use `umask 077` + `chmod 0600`, and `UMask=0077` on the units.
- **A root loop reading an account-owned file needs `[ -f ] && [ ! -L ] && timeout 5 …`.** A FIFO marker hung a plain `grep` (the quota loops too).
- **Never `setfacl --restore` a tree.** It rewrites the WHOLE ACL from the dump and follows a symlink swapped in after the dump (`-P` does not cover it). Grant files with `find -exec setfacl -P -n -m u:x:r--`: a `---` entry (a file born under the closed home default) becomes `r--` under the file's OWN mask, so the owner's `chmod g+r` / `g-r` decides; report such files once. `chmod g+r` never opens a named `---` entry, so never advise it for one.
- **Tests:** a non-root test cannot probe as another uid. Run real setfacl with `nobody`/`daemon` as stand-ins and owner-permission proxies for the checker; under root (the CI container), hand the probed files to `nobody` and probe through `runuser`. SAVE every record stream the read-back receives (round-1 mutants survived because the stub discarded them). CI's Debian awk is mawk; run the behavioural suites with the script's `awk -v`/`-F` calls forced to mawk. A mutation driver must set `PYTHONPYCACHEPREFIX` to a fresh dir: two equal-size mutants written in the same second reuse a stale `.pyc` and "survive".
